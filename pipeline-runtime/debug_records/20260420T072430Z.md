## 新观察

### 1. 当前 wrapper 的总 watchdog 默认已经是 10800s，但 host monitor 的 guest-idle timeout 仍只有 600s

- `scripts/firesim-tmux-run.sh`
  里的 runworkload watchdog 默认是 `10800s`
- 但 `scripts/firesim-prt-host-watchdog.sh`
  的 `idle_timeout_seconds`
  默认仍是 `600s`
- 因而当前真正过早回收实例的，是 host monitor 这层更激进的 guest-idle 逻辑

### 2. 不能直接把 heartbeat 当作 progress，否则会让 watchdog 对“guest 自旋但仿真仍活着”失去约束

- 若简单把 heartbeat 推进直接重置 `last_progress_epoch`，
  那么只要 target 还在跑，
  host monitor 几乎永远不会因为 guest-visible stall 回收实例
- 这会把当前误杀修掉，
  但也会让未来对真实 software deadlock 的自动 capture 变得过弱

## 本轮修改

### 1. host watchdog 改为“双层超时”

- 继续保留原来的 `idle_timeout_seconds`，
  但它现在只在：
  - guest-visible 文件长时间不增长
  - 且 heartbeat 也已经 stale
  时触发
- 新增：
  `live_idle_timeout_seconds`
  默认 `10800s`
- 当 heartbeat 持续前进、但 guest 文件长时间不增长时：
  - 不再在 `600s` 误杀
  - 改为等待更长的 `live_idle_timeout_seconds`

### 2. 新增 heartbeat liveness 跟踪

- 记录：
  - `last_hb_line`
  - `last_heartbeat_epoch`
- 新日志里会同时打印：
  - `idle=<guest-visible idle>`
  - `hb_idle=<heartbeat idle>`
- 若本轮只有 heartbeat 前进、没有 guest 文件增长，
  会额外打印：
  `heartbeat-progress ...`

### 3. wrapper help 增加了新环境变量说明

- 新增可覆盖变量：
  `FIRESIM_RUNWORKLOAD_LIVE_IDLE_TIMEOUT_SECONDS`

### 4. tmux wrapper 继续透传 trigger overlay 环境变量

- `scripts/firesim-tmux-run.sh`
  现在除了透传 `FIRESIM_*` 之外，
  也会把
  `PIPELINE_RUNTIME_DEBUG_TRIGGER_*`
  一并带进 detached `tmux` session
- 目的不是改变当前默认 profile，
  而是确保后续若需要按 SOP 做
  trigger-gated 单变量 overlay，
  overlay 不会在 wrapper 边界被静默丢失

## 本轮结论

- 当前最小且更稳妥的 host-side 修法，不是“heartbeat = progress”，
  而是：
  **把 heartbeat 当作 liveness 信号，用更长的 live-idle 超时来替代当前 600s 的误杀。**
- 这样既能保住当前 `g6 bertmini` 的长静默 pointwise 窗口，
  也不会彻底取消 host watchdog 对真实 stall 的兜底能力。
