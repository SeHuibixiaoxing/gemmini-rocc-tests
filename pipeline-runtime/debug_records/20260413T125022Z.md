## Context

- Target: `pairdummy-sbus128` dummy-model on 12-pair `sbus128` hardware.
- Goal: continue locating the real stall on `segment=0 stage=0 tensor=2 export`.
- Prior live run remained active on host heartbeat, but guest sparse log froze after:
  - `dma-export-host stage=0 tensor=2 phase=page-submitwait-end page=32/64 ...`
  - no later `page=40/64 begin`
- Prior token-window probe (`2698..2720`) did not emit any `dma-export-submit` / `dma-export-wait` inner logs, so the guessed token window was not trustworthy.

## Problem Reframing

- A simple "return token id to caller" change is insufficient:
  - if the call blocks inside submit/wait, caller never regains control
  - therefore caller cannot print the token for the stuck page
- The better low-disturbance approach is:
  - narrow page-level probing to the suspected page interval
  - force already-existing inner export submit/wait probe logs for those pages only
  - let those existing inner logs print the true `tok=...`
