## Switch evidence

Captured switchlog:


The corruption is already present when the switch receives flits from the
target side:


Those bytes are little-endian:


and match the corrupted `$PackEtSize=` string later written to TAP:

```text
SWITCH DEBUG SSHPort tap_send_bytes port=1 event=6 off=64 bytes=... 24 50 61 63 6b 45 74 53 69 7a 65 3d ...
```

So the current failure is at or before target-to-switch shared-memory receive.
`SSHPort` forwards the corrupted payload and recomputes IPv4/TCP checksums.

## Interpretation

Current old-AGFI status:

- Linux boot: pass
- IceNet registration and network script: pass
- `gdbserver` prelaunch: pass
- TCP handshake: pass after ARP/control checksum repair
- RSP payload integrity: fail
- old software-breakpoint GDB capability matrix: not yet restored

The current `a300ebdfe` payload checksum repair is useful but insufficient:
it converts a host-side packet drop into a deterministic GDB parse failure.
The payload corruption itself remains upstream of `SSHPort`.

One likely regression is the reintroduced ShmemPort empty-marker preservation
in `a3cc758c6`. Commit `341c41986` restored clearing the
`0xDEADBEEFDEADBEEF` compressed-empty marker before publishing a full
shared-memory buffer, but `a3cc758c6` reverted that back to preserving the
marker. The old AGFI was built from FireSim commit `9920b291...`, whose
`ShmemPort::send()` cleared the marker. The next control should keep the
ARP/TCP checksum repair but restore marker clearing.
