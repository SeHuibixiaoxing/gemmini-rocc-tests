### 2. 改成 host-only 的 `CPUManagedStream` 失败诊断

修改文件：

- `/home/ubuntu/chipyard/sims/firesim/sim/midas/src/main/cc/bridges/cpu_managed_stream.h`
- `/home/ubuntu/chipyard/sims/firesim/sim/midas/src/main/cc/bridges/cpu_managed_stream.cc`

新增能力：

- 给 `CPUManagedDriver` 增加 `stream_name()` accessor
- 在 `CPUToFPGADriver::push()` 因 occupancy 不足而返回 `0` 时打印：
  - `stream_name`
  - `count_addr`
  - `dma_addr`
  - 当前 `count`
  - `fpga_buffer_size`
  - `space_available`
  - `requested_bytes`
  - `required_bytes`
  - `requested_beats`
  - `threshold_beats`
  - `beat_bytes`
- 在 `FPGAToCPUDriver::pull()` 因数据不足而返回 `0` 时，也打印同类信息

这条日志能直接回答：

- 为什么 `push()==0`
- 是不是 `count` 已经接近 `fpga_buffer_size`
- 是空间不足，还是阈值要求太高

### 3. `simplenic` 只补 host 上下文，不再读 target 新寄存器

修改文件：

- `/home/ubuntu/chipyard/generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.h`
- `/home/ubuntu/chipyard/generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.cc`

新增：

- `dump_host_debug(...)`

它在以下失败点打印纯 host 上下文：

- `init_pull_expected_empty`
- `init_push_capacity`
- `tick_pull_mismatch`
- `tick_push_mismatch`

打印内容包括：

- `currentround`
- `LINKLATENCY`
- `stream_to_cpu_idx`
- `stream_from_cpu_idx`
- `BUFBYTES`
- `loopback`
- `done`
- `write_poll`
- `read_poll`

因此下一轮失败时，输出会变成两层：

1. `CPU_STREAM DEBUG ...`
   直接说明 stream occupancy / threshold 为什么导致 `0-byte`
2. `SIMPLENIC DEBUG ...`
   给出当前 host round/context，方便把失败挂回 `simplenic` 的执行阶段
