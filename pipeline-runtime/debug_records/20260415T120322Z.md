## Static Findings Before Rerun

### 1. `target_seq=1` 不是“重复 alias 被跳过”

`copy_tensor_pages_to_model_aliases()` 位于：

- `src/prt_runtime.c:1913`

其中 `address` 与 `address2` 都会分别做：

- `resolve_model_addr_to_ptr()`
- `alias_target_seen_find()`
- `copy_tensor_pages_to_model_alias_target()`

只有目标地址和大小都相同才会被 `repeat` 去重。

上一轮 sparse log 已显示：

- `target_seq=0 phase=end`
- 紧接着 `target_seq=1 phase=begin`

这说明当前 `address2` 目标不是被 repeat-skip，
而是真的进入了第二次 export。

### 2. 第二次 export 的静态执行路径

代码链路已经确认：

- `src/prt_runtime.c:1850`
  `copy_tensor_pages_to_model_alias_target()`
- `src/prt_dma.c:2270`
  `prt_dma_copy_spm_pages_to_dram()`
- `src/prt_dma.c:700`
  `dma_copy_spm_pages_to_host_linux()`

在 Linux guest 上，
export 到 host/model-alias 目标时会进入：

1. `dma_batch_scope_acquire()` 先拿 RR scope
2. 按 host 页边界切 chunk
3. `prt_host_virt_to_phys(dst_ptr, &dst_pa)`
4. `dma_submit_wait_annotated_scoped()`

因此上一轮 breadcrumb 停在：

- `prt_rerocc.c:332`
- `rr_acquire_after_call`

它只说明第二个 export target 已完成 RR acquire；
尚不能区分是：

- acquire 之后的 `virt_to_phys`
- 还是后续 page submit/wait

### 3. `address2` 目标本身仍落在 `model_blob`

`resolve_model_addr_to_ptr()` 位于：

- `src/prt_runtime.c:860`

`address2[j]` 和 `address[j]` 一样，
最终都解析到：

- `rt->model_blob + model_blob_offset + off`

因此当前问题不是：

- 目标地址跑到了 UART/log 缓冲区
- 或者跑到了额外文件映射

它仍是 model blob 内的第二个别名目标。

## Working Hypothesis

当前最可能的新窗口是：

- 第二个 export target (`target_seq=1`)

- 进入 `dma_copy_spm_pages_to_host_linux()` 的早期阶段
