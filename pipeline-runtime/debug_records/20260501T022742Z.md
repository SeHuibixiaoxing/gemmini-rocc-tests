## 注意事项

本轮 batch gdb 末尾使用了：

```gdb
continue
quit
```

因此 gdb 报：

```text
Cannot execute this command while the target is running.
Use the "interrupt" command to stop the target and then try again.
```

这不是 NIC/gdbserver 链路失败，而是 batch gdb 脚本收尾方式不干净。SOP 中已经记录：若只验证调试能力，应在断点处采样后 `detach`；若要 workload 自然 PASS，应交互式 `continue` 到 inferior 退出，再观察 `[gdbserver] phase=exit` / poweroff。

## 结论

1. NIC 基础通信、Linux boot、IceNet、guest TCP、SSH tunnel、cross-gdb RSP 链路均已打通。
2. 之前的 SimpleNIC 空轮询/boot 迟滞问题已向前推进，不再是当前 blocker。
3. 当前剩余工作不是硬件修复，而是把 remote gdbserver SOP 固化成干净的 first-attach 操作流程，避免 `gdbserver --once` 被不规范 batch 脚本消耗。
