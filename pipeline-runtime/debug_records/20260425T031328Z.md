## 输入证据

- 上一轮 FPGA 失败点：
  - `ERR MISMATCH! on writing tokens in. actually wrote in 0 bytes, wanted 58560 bytes.`
  - `SIMPLENIC DEBUG [tick_push_mismatch]`
  - `t_fire_blocked_from_host_ready=1`
  - `hport_from_host_ready=0`
- 上一轮静态结论：
  - `hport_from_host_ready` 是 `HostPort` 聚合 ready，不是 NIC 局部 ready。
  - 生成后的 `SimpleNIC` sink ready 受全局 `targetCycleFinishing` 门控。
  - 当前本地 lockstep patch 让 `fromHost.hValid` 依赖 `fromHost.hReady`，可能把一次全局 backpressure 放大成稳定闭锁。

## 本轮实现

### 1. 拆掉 `fromHost.hValid -> fromHost.hReady` 组合依赖

修改：

- `/home/ubuntu/chipyard/generators/firechip/goldengateimplementations/src/main/scala/SimpleNICBridge.scala`

新的核心信号：

- `localQueuesReady = ntht_queue.io.enq.ready && htnt_queue.io.deq.valid`
- `targetCycleReady = hPort.toHost.hValid && hPort.fromHost.hReady`
- `fromHostValidDrive = hPort.toHost.hValid && localQueuesReady`
- `toHostReadyDrive = hPort.fromHost.hReady && localQueuesReady`
- `tFire = targetCycleReady && localQueuesReady`

关键语义：

- `hPort.fromHost.hValid := fromHostValidDrive`
- `hPort.toHost.hReady := toHostReadyDrive`
- `ntht_queue.io.enq.valid := tFire`
- `htnt_queue.io.deq.ready := tFire`
- `target.in.valid := htnt_queue.io.deq.bits.data_in_valid && tFire`

这样保留了“真正消费 token 时 host/target 双向同拍推进”的约束，但不再让 `fromHost.hValid` 被 `fromHost.hReady` 反向撤掉。

### 2. 增加下一颗 bitstream 可直接读出的硬件观测点

新增/保留的 `SimpleNICBridge` MMIO 观测点包括：

- `local_queues_ready`
- `target_cycle_ready`
- `to_host_ready_drive`
- `from_host_valid_drive`
- `htnt_queue_enq_ready`
- `htnt_queue_deq_valid`
- `ntht_queue_enq_ready`
- `ntht_queue_deq_valid`
- `target_in_bits_data_lo/hi`
- `target_in_bits_keep/last`
- `target_out_bits_data_lo/hi`
- `target_out_bits_keep/last`

目的：

- 下一轮若 FPGA 仍失败，host log 能区分：
  - 本地 queue 是否真的阻塞
  - 全局 target-cycle ready 是否阻塞
  - bridge 实际驱动给 HostPort 的 ready/valid 是什么
  - 失败拍附近 NIC 输入/输出 token 内容是否为空或异常

### 3. 增强 host-side `simplenic` 诊断

修改：

- `/home/ubuntu/chipyard/generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.cc`
- `/home/ubuntu/chipyard/generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.h`

新增 plusargs：

- `+simplenic-round-debug=N`
- `+simplenic-round-debug0=N`
- `+simplenic-relaxed-required-bytes=1`
- `+simplenic-relaxed-required-bytes0=1`
- 也支持 flag 形式 `+simplenic-relaxed-required-bytes`

语义：

- `round-debug`：前 N 个成功 round 也打印一次完整 `SIMPLENIC DEBUG` 快照。
- `relaxed-required-bytes`：把 stream `pull/push` 的 required threshold 降到 `0`，但仍保留整批字节数 mismatch fatal check；用途是诊断“完全无空间/无数据”和“有部分空间/部分数据但没达到整批阈值”的差异。
