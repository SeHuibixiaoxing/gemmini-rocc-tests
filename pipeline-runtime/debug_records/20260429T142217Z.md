## 新的静态根因收敛

F2 顶层此前把整个 `F1Shim` 置于：

```systemverilog
.reset(!rst_firesim_n_sync || !ddr_ready_sync)
```

这会把 `SimulationMaster` 所在的 OCL 控制面也一起受 `ddr_ready_sync` 门控。上一轮硬件现场已经证明 shell 收到了 OCL transaction 但 CL 没有返回；结合 `PRESENCE_WRITE` 复位值应非 0，最直接的解释是 F1Shim/control plane 在 fingerprint read 期间仍处于 reset 或不可响应状态。

这个门控对 FireSim manager 启动顺序不成立：driver 必须先能通过 OCL 读写 `SimulationMaster` 控制寄存器，才有机会完成 fingerprint、初始化模拟器和继续走后续 workload。DDR 是否 ready 可以用于后续 target/DRAM 有效性判断，但不能把 OCL 控制寄存器本身按在 reset 里。

## 本轮硬件修复方向

修改 F2 顶层：

```systemverilog
.reset(!rst_firesim_n_sync)
```

同时新增 host-visible 可综合状态输出到 `cl_sh_status0/1/2` 和 `cl_sh_status_vled`，覆盖：

- `rst_main_n`、`rst_main_n_sync`、`firesim_clocking_locked`、`rst_firesim_n_sync`；
- `ddr_ready`、`ddr_ready_sync`，以及旧门控条件 `!ddr_ready_sync`；
- shell-side OCL AW/W/B/AR/R valid-ready；
- F1Shim-side OCL AW/W/B/AR/R valid-ready；
- OCL read/write fire 计数；
- PCIS width bridge 的 FSM state 和 narrow/wide fire 计数低位；
- PCIS response error 的 virtual LED 摘要。

下一轮即使 `+check-fingerprint` 仍失败，也可以用 `fpga-describe-local-image -M` 在不依赖 FireSim driver 成功启动的情况下读取 reset、DDR ready、OCL handshakes 和 PCIS bridge 状态。
