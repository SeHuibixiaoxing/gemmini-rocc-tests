## 关键新证据

SimpleNIC direction-fire 修复确实生效：

```text

```

这说明上一轮怀疑的 `fromHostValidDrive` 被撤掉问题已经不再成立。本轮失败现场中：

```text
hostport to_host(v=0 r=1) from_host(v=1 r=0)
drives local_queues_ready=1 target_cycle_ready=0 to_host_ready_drive=1 from_host_valid_drive=1
current_blocked_reason=0x63
```

也就是说：

- SimpleNIC 本地 `htnt` 有 token，`fromHostValidDrive=1`。
- `toHost` 方向此刻不堵。
- 真正堵的是 `fromHost.hReady=0`，来自 FPGATop / target-cycle 层。

TargetCycle `last` 快照：

```text
BlockDevBridgeModule     to(v=1 r=0)
UARTBridgeModule         to(v=1 r=0)
SimpleNICBridgeModule    to(v=0 r=1) from(v=1 r=0)
```

同时：

```text
TARGETCYCLE DEBUG BLOCKER [last] hport_to_host_blocked[3] ep_1:UARTBridgeModule
TARGETCYCLE DEBUG BLOCKER [last] hport_from_host_blocked[5] ep_3:SimpleNICBridgeModule
```

因此当前不是 NIC 局部队列无 token / 无空间，也不是本轮改动没有部署。新前沿已经上移到 global HostPort aggregation / `targetCycleFinishing`。

## 静态展开

生成 SV 中 SimpleNIC 自身已经是期望的方向独立式：

```text
assign hPort_toHost_hReady = ntht_queue_io_enq_ready;
assign hPort_fromHost_hValid = htnt_queue_io_deq_valid;
assign ntht_queue_io_enq_valid = hPort_toHost_hValid & hPort_toHost_hReady;
assign htnt_queue_io_deq_ready = hPort_fromHost_hValid & hPort_fromHost_hReady;
```

FPGATop 生成逻辑显示：

```text
SimpleNICBridgeModule_0_hPort_fromHost_hReady =
  all ep_3_nic_*_sink_ready

ep_3_nic_*_sink_ready =
  targetCycleFinishing & ~ep_3_nic_*_fired_0

targetCycleFinishing =
  all source channel fired/ready/valid
  AND all sink channel valid
```

当前 `last` 快照中大量 wire input sink valid 缺失、wire output blocked，同时 UART/BlockDev 也有 toHost blocker。因此 `targetCycleFinishing` 没有成立，反过来使 NIC `fromHost.hReady` 保持 0。

## 当前结论

本轮修复推进了问题：

- 已修复：SimpleNIC 不再因为 `toHost.hValid` 下降而撤掉 `fromHost.hValid`。
- 新前沿：global HostPort / target-cycle 聚合层仍会在早期 NIC tick 中形成 `fromHost.hValid=1, fromHost.hReady=0`，并最终让 from-cpu stream FIFO 被填满。

下一步不应再只改 SimpleNIC 本地队列。更合理的方向是：

1. 静态审计 `HostPortIOConnectChannels2Port` 里 `fromHostChannels.foreach(ch.valid := DecoupledHelper(... ready ...))` 与 `targetCycleFinishing` sink-ready 之间的依赖。
2. 对 UART / BlockDev / TSI / FASEDMemory 的 HostPort lockstep bridge 语义做同类展开，因为本轮 last snapshot 已经同时出现 UART/BlockDev toHost blocker。
3. 若继续构建新 bitstream，应在 FPGATop/TargetCycleDebugWidget 加更精确的 per-channel fired-state 和 `targetCycleFinishing` 输入项快照，直接标出哪几个未 fired 项阻止了 finishing。
