## Test 1: SSHPort TAP repair unit test

File:

- `sims/firesim/target-design/switch/tests/sshport_repair_test.cc`

Command:

```sh
g++ -std=gnu++11 -Wall -Wextra \
  -I /home/ubuntu/chipyard/sims/firesim/target-design/switch \
  -o /tmp/sshport_repair_test \
  /home/ubuntu/chipyard/sims/firesim/target-design/switch/tests/sshport_repair_test.cc
/tmp/sshport_repair_test
```

Result:

```text
PASS sshport_repair_test
```

Coverage:

- ARP sender hardware address repair copies Ethernet source MAC into ARP SHA.
- IPv4/TCP checksums are repaired for payload-bearing TCP frames where source
  or destination port is `2345`.
- Payload-bearing non-GDB TCP flows are left untouched.
- Zero-payload TCP control frames are checksum-repaired even when they are not
  on port `2345`.

Interpretation:

- This confirms the recovered-driver old-AGFI pass is not relying on an
  obviously broken TAP repair helper.
- It does not prove packet payloads are generated correctly by hardware.

## Test 2: DDR-stat split `lib_pipe` xsim test

File:

- `sims/firesim/platforms/f2/aws-fpga-firesim-f2/hdk/cl/developer_designs/cl_firesim/verif/tests/test_lib_pipe_ddr_stat_split.sv`

Commands, run from
`sims/firesim/platforms/f2/aws-fpga-firesim-f2`:

```sh
xvlog -sv hdk/common/lib/lib_pipe.sv \
  hdk/cl/developer_designs/cl_firesim/verif/tests/test_lib_pipe_ddr_stat_split.sv
xelab test_lib_pipe_ddr_stat_split -s test_lib_pipe_ddr_stat_split_sim
xsim test_lib_pipe_ddr_stat_split_sim -runall
```

Result:

```text
PASS test_lib_pipe_ddr_stat_split
```

Coverage:

- `STAGES=8` request-side `wdata`, `addr`, `wr`, and `rd` pipes preserve
  alignment.
- Response-side `rdata`, `ack`, and `int` pipes preserve alignment.
- Control pipes using `rst_n` clear asynchronously.
- Data-only pipes tied to `rst_n=1'b1` continue advancing after reset; this is
  acceptable because their consumers should only sample data when a resettable
  control signal is asserted.

Interpretation:

- The split DDR-stat pipe change has the intended local latency/reset semantics.
- This does not prove Vivado can close timing or that DDR init/status behavior
  is correct in a full F2 shell build.
