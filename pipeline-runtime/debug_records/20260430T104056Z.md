## 静态排查结论

本轮重点检查 `SimpleNIC` host driver 与 FPGA-side bridge 是否仍存在语义不一致。

### host driver 语义

文件：

- `generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.cc`
- `generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.h`

关键事实：

- relaxed 模式下 `required_pull_bytes = 0`，host driver 允许 target->host stream 本轮没有数据。
- target 无数据时，driver 仍发布一个空 shmem round 给 software switch，让 switch 能处理 host TAP 侧输入。
- switch peer 没有 host->target payload 时，`pending_peer_valid_flits == 0`，driver 执行
  `tick_peer_empty_skip_push`，不再把空 token 写回 FPGA from-host stream。
- 代码注释明确写明：FPGA-side bridge 现在会自生成稳定 no-packet host input token，因此 empty switch round 不需要 replay 到 CPU-managed from-host stream。

这说明 host 侧已经不再依赖“每轮都向 FPGA push 空 token”来推进 target。

### FPGA-side bridge 语义

文件：

- `generators/firechip/goldengateimplementations/src/main/scala/SimpleNICBridge.scala`

关键事实：

- `fromHostValidDrive = true.B`
- `hPort.nicIn.valid := fromHostValidDrive`
- `hPort.nicIn.bits.valid := fromHostCurrentPayloadValid`
- 无 payload 时，target 仍持续看到一个 ready/valid 层面有效、payload valid 为 0 的 no-packet token。
- `htnt_queue.io.deq.ready := fromHostEmptyDrop || fromHostPayloadCapture`
- empty CPU-stream token 会在 bridge 内部丢弃，不会在队列里堆出无界 no-op backlog。
- `from_host_valid_drive`、`from_host_current_payload_valid`、`from_host_empty_drop`、
  `target_cycle_ready` 等寄存器已经出现在本地生成的
  `sims/firesim/sim/generated-src/f2/f2-firesim-FireSim-FireSimRocketNICNoTraceConfig-BaseF2Config/FireSim-generated.sv`
  与 `FireSim-generated.const.h` 中。

这说明当前源码层面 host driver 与 FPGA-side bridge 的 no-packet 语义是对齐的。

## 当前确定判断

当前没有新的、已经被静态证据钉死的 SimpleNIC RTL 逻辑错误。

新一轮 single-core bitstream 的必要性来自版本一致性验证，而不是已经定位到一个必须修的新 RTL 点：

- 本地 driver bundle 是 `2026-04-30 09:52 UTC` 后生成的；
- 本地 single-core Verilog 是 `2026-04-29 05:22 UTC` 生成的，并且包含 `from_host_valid_drive` 等关键 debug/safety 信号；
- 已验证的 AGFI `agfi-019e0b22099a5214b` 已经能跑通 remote gdbserver，但继续构建一颗最新 single-core AGFI 可以排除“本地源码、driver、Verilog、AGFI 不是同一版”的风险。

新 build 启动后必须执行 freshness gate：

1. 检查 manager 本地 config-specific generated Verilog 是否包含：
   `from_host_valid_drive`、`from_host_current_payload_valid`、`from_host_empty_drop`、
   `target_cycle_ready`。
2. 检查 host driver source/build 是否包含：
   `tick_peer_empty_skip_push`、`+simplenic-relaxed-required-bytes`。
3. 远端 build host 起来后，检查远端 `/home/ubuntu/firesim-build/.../FireSim-generated.sv`
   同样包含上述信号，避免再次出现“启动了构建但 Verilog 没包含最新改动”的问题。
