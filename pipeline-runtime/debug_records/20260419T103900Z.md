## 设计要点

### 1. 保持 pair-manager 语义，但把负载缩到最小

- 编译默认固定为：
  - `NUM_CORES=4`
  - `NUM_GEMMINI=12`
  - `NUM_DMA=12`
  - `GEMMINI_BASE_ID=0`
  - `DMA_BASE_ID=0`
  - `PAIR_MANAGER_MODE=1`
- 但实际执行只用 hart0、manager0、cfg0。
- 指令链只保留：
  - acquire
  - `RROPC3 <- cfg0`
  - `RROPC2 <- cfg0`
  - 一条 `4096B` DMA
  - `rr_release`
  - 目标哨兵：
    `RRCFG readback` 或 `RROPC3 restore`

### 2. 默认模式选 `mode=2`

- 默认编译模式：
  `raw release -> immediate RROPC3 restore`
- 这是最接近
  “日志已经到 restore-begin，但后继 `RROPC3 csrrw` 可能不退休”
  的最小协议证明。

### 3. 低扰动日志只包围单条目标指令

- 关键输出顺序是：
  - `before-raw-release`
  - `after-raw-release`
  - `before-readback`
  - `after-readback`
  或
  - `before-restore-opc3`
  - `after-restore-opc3`
- 这样如果最后一条 UART 停在 `before-*`，
  就可以直接把 blocker 归到紧随其后的那条 CSR 指令。

### 4. 已把 TraceV instruction marker 直接编进最终 ELF

- start marker：`.word 0x00008013`
- end marker：`.word 0x00010013`

## 当前结论

- “不要 Linux metasim” 这个约束已经落实到工件层面，
  后续不需要再穿过 Linux boot / guest 文件系统这条慢路径。
- 现在已经有一个 **pair-manager 语义不变**、但 **指令窗口极小** 的 baremetal probe，
  能直接回答：
  - 是 `release ack / RRCFG readback` 在挡
  - 还是紧邻的 `RROPC3 restore` 在挡

## 下一步建议

1. 用 local metasim 跑这条 baremetal probe。
2. 第一轮保持默认 `mode=2`。
3. 若 UART 最后停在 `before-restore-opc3`，
   直接记为：
   “next RoCC CSR = `RROPC3 csrrw` 被 busy 挡住”。
4. 若需要对照 release ack，
   再切 `mode=1` 复编一次，
   比较 `before-readback` / `after-readback`。
