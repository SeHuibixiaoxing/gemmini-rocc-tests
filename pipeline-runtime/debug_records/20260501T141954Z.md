## 本轮静态结论

现有可综合观测已经有：

- `hPort.nicOut` 最新包 first16；
- `NICTokenToBigTokenAdapter` 最后一次 `pcie_out` bigtoken words；
- host `target_to_switch_pull` token buffer dump。

但这些还不能一次性钉死 bit-clear 的第一个出现边界，因为缺少同一包在
`NICTokenToBigTokenAdapter.ntht` 输入和 `pcie_out` 输出处的 first16 持久快照。

下一轮如果只看到：

- `hPort.nicOut` 已坏：问题在 IceNet TX / send path / StreamReader / Aligner 侧；
- `hPort.nicOut` 好、adapter `ntht` 坏：问题在 `ntht_queue` 或其连接；
- adapter `ntht` 好、adapter `pcie_out` 坏：问题在 `NICTokenToBigTokenAdapter` packing；
- adapter `pcie_out` 好、host pull 坏：问题在 CPU-managed stream / F2 PCIS read bridge / host readback。

因此本轮新增的观测点是必要的，不是继续围绕旧的 boot/ARP/TCP 连通性问题转圈。
