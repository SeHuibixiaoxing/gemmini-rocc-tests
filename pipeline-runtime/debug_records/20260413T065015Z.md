# Debug Record 20260413T065015Z

## Scope

- Start a new debug round after discovering that the narrowed export-probe envs did not actually reach the guest.
- This means the previous rerun was built from updated sources, but the guest runtime still used the old wide probe behavior.

## Root Cause Discovered

- Remote freshness and direct `debugfs -R 'cat /firemarshal.env'` on the run host image showed:
  - `PIPELINE_RUNTIME_PROFILE_ID='pairdummy-sbus128-fixed-v2'`
  - `PIPELINE_RUNTIME_MLOCKALL_MODE='2'`
  - `PIPELINE_RUNTIME_DMA_SUBMIT_TRACE_ENABLE='0'`
  - but **no**
    - `PIPELINE_RUNTIME_DMA_EXPORT_PROBE_ENABLE`
    - `PIPELINE_RUNTIME_DMA_EXPORT_PROBE_TOKEN_START`
    - `PIPELINE_RUNTIME_DMA_EXPORT_PROBE_TOKEN_END`
- Therefore the prior rerun was invalid for the intended narrowed-probe experiment.

## Why This Happened

- `pairdummy_sbus128_fixed_env.sh` exported the new env vars on the host.
- But workload guest-env generation in:
  - `rerocc-linux-tests-coupleddma/workload/host-init.sh`
  - uses an explicit whitelist array for `/firemarshal.env`
- The new export-probe env names were missing from that whitelist.
- Also, guest runner invocation in:
  - `rerocc-linux-tests/run_rerocc_pipeline_runtime_bertmini.sh`
  - explicitly forwards some debug envs to the runtime binary, and the new export-probe envs were missing there too.

## Fix Applied

- `rerocc-linux-tests-coupleddma/workload/host-init.sh`
  - added to the generated guest env whitelist:
    - `PIPELINE_RUNTIME_DMA_EXPORT_PROBE_ENABLE`
    - `PIPELINE_RUNTIME_DMA_EXPORT_PROBE_TOKEN_START`
    - `PIPELINE_RUNTIME_DMA_EXPORT_PROBE_TOKEN_END`
- `rerocc-linux-tests/run_rerocc_pipeline_runtime_bertmini.sh`
  - added shell defaults for those three envs
  - added them to the runner log summary line
  - forwarded them into the runtime binary process environment

## Static Checks

- `bash -n` passed for:
  - `rerocc-linux-tests-coupleddma/workload/host-init.sh`
  - `rerocc-linux-tests/run_rerocc_pipeline_runtime_bertmini.sh`
