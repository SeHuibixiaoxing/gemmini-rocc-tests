## 静态结论

重新核对 `ChannelizedHostPortIO` 与 `FPGATop` 连接逻辑：

- `OutputChannel` 会把 bridge 端 `channel.valid` 直接接到 target
  `wireInput.valid`。
- target 端 `wireInput.ready` 再反接到 bridge 端 `channel.ready`。
- 因此 host->target 的 `valid` 不能等待 target-side `ready`，
  否则会形成 ready/valid dependency loop。

当前源码曾再次出现与前几轮结论冲突的写法：

```scala
val fromHostValidDrive = targetCycleReady
```

已修正为：

```scala
val fromHostValidDrive = fromHostTokenAvailable
```

并保留整组 target cycle 对 `htnt_queue.io.deq.ready` 的门控：

```scala
htnt_queue.io.deq.ready := targetCycleReady
```

结论：这是继续向前推进，不是在旧问题上原地转圈。它修正的是
empty-token / atomic-cycle 改动过程中重新引入的 ready/valid 互等回归。
