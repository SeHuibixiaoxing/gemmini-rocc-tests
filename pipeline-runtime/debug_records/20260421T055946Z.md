## 分析

### 为什么本轮可以直接视为已收敛

- 现在新增的所有落盘都来自：
  - `heartbeat.csv`
  - host watchdog 自身
  - FireSim manager 状态刷新
- 与真正调试主线相关的 guest 证据已经稳定冻结：
  - `uartlog` 停住
  - `TRACEFILE` 停住
  - guest log / checkpoint / trigger 都停住
- 同时又新增了足够强的新事实：
  - Linux 已经报出 `rerocc_pipeline` 相关 `RCU stall`
- 因而继续等待 3 小时不会提高这轮的信息增益

### 为什么这轮不应再依赖 10800s 的 live-idle

- 当前 mainline 调试目标是快速确认“是否又进入稳定 plateau”
- `10800s` 更像“避免误杀一切 heartbeat-live run”的保守值
- 对 `pairdummy pipeline-runtime` 当前这条主线，它过长，
  会显著浪费 F2 机时并拖慢下一轮引入 `gdb/gdbserver` 的准备
