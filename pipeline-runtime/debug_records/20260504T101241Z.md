## 结论

用户指出一个关键流程问题：不能在 `buildbitstream` 已经运行时继续边想边追加硬件观测点。
这个约束已经固化：

- 新 bitstream 启动前必须先完成静态排查、历史记录复核、观测点清单冻结和静态校验。
- 构建启动后只允许做 RTL freshness gate，确认启动前已经冻结的改动进入 config-specific Verilog / 远端 build host。
- 如果构建中又发现新的硬件观测需求，只能记为下一轮候选，不能把正在构建的 AGFI 当成包含后补改动的版本。

  记录最近 emit slot、所有 emit slot、所有 payload emit slot，判断 7 个 slot 是否完整推进。

  记录 flush candidate / flush blocked，以及 pcie_out queue enqueue valid-but-not-ready 计数。

  单独暴露 `nicIn/macAddr/rlimit/pauser` leaf valid/ready/fire/blocked mask。
- target-cycle：
  记录 first ready / first fire cycle，以及 ready/not-ready streak 和 max streak。
- from-host / to-host 卡点：
  记录 would-blocked、leaf-blocked、每个 leaf blocked/fire 计数、payload queue blocked streak。
