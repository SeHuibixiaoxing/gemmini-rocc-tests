# NIC target-to-host payload corruption: non-coherent DMA driver bug

日期：2026-04-30T03:57:26Z

## 本轮目标

接续 `singlecore + NIC + Linux + gdbserver` F2 调试。上一轮关闭 IceNet checksum offload 后，target/host 双向通信仍然成立，但 target->host payload 仍出现确定性的 bit-clear 损坏。本轮先静态排查，争取不用新 bitstream。

## 动态现场事实

最新可复查现场：

- `tmp/firesim-aws-f2/nic-scenes/live-20260430-nocsum-tapfix-final/`
- `sims/firesim/deploy/results-workload/2026-04-30--02-34-04-rocket-singlecore-nic-gdbserver-smoke-f2-rocket-singlecore-nic-gdbserver-smoke-notrace-relaxed-noprint-longheartbeat-preserve/`

关键现象：

- checksum offload 已关闭，uartlog 中没有 TXCSUM/CSUM enable 路径。
- target->host 的损坏已经出现在 host-side `simplenic` 的 `target_to_switch_pull`，并在 `switchlog` 的 `ShmemPort recv` 中保持一致。
- `uartlog` 第 4091-4104 行附近，event 26 的 all-ones payload 已经出现：
  - `data=0xfeffffffffffffff`
  - `data=0xfffffffdffffffff`
- `switchlog` 第 305 行同一个 event 26 也收到：
  - `sample2=0xfeffffffffffffff`
- 因此本轮不再把 switch/TAP、BIGToken host parser、StreamWidthAdapter lane 顺序、或者 IceNet checksum rewrite 当作首要根因。

## 静态证据

### 1. target Linux 明确是 non-coherent DMA 环境

生成 DTS 中的 IceNIC 节点：

- `sims/firesim-staging/generated-src/firechip.chip.FireSim.FireSimRocketNICNoTraceConfig/firechip.chip.FireSim.FireSimRocketNICNoTraceConfig.dts`
- 第 111-117 行 `ice-nic@10016000` 只有 `compatible`、`interrupts`、`reg`、`reg-names`。
- 该节点没有 `dma-coherent`。

Linux config：

- `software/firemarshal/boards/default/linux/.config`
- 第 286 行：`CONFIG_RISCV_DMA_NONCOHERENT=y`
- 第 3423-3424 行：`CONFIG_ARCH_HAS_SYNC_DMA_FOR_DEVICE=y` / `CONFIG_ARCH_HAS_SYNC_DMA_FOR_CPU=y`
- 第 3427 行：`CONFIG_SWIOTLB=y`

这三点合在一起说明：IceNIC DMA 不能直接假设 CPU cache 与设备视角自动一致，driver 必须使用 Linux DMA mapping API。

### 2. 原 IceNet driver 没有使用 DMA API

原始 driver 的 TX/RX 做法是：

- TX linear skb：`virt_to_phys(skb->data)` 后写 `ICENET_SEND_REQ`
- TX frag：`page_to_phys(frag->bv_page) + frag->bv_offset`
- RX skb：`virt_to_phys(skb->data)` 后写 `ICENET_RECV_REQ`
- completion 时没有 `dma_unmap_*`

这在 coherent 平台上可能侥幸可用；在当前 RISC-V non-coherent Linux 上是确定错误。CPU 写 skb 并计算 checksum 后，如果没有 `dma_map_single(..., DMA_TO_DEVICE)`，设备可能读到旧 cacheline 或未同步内存；设备写 RX skb 后，如果没有 `dma_unmap_single(..., DMA_FROM_DEVICE)`，CPU 也可能读到旧内容。

这个错误能解释当前最关键的形态：checksum 字段匹配 CPU 视角的“正确 payload”，但线上 payload 被 DMA 读成旧值或部分旧值，所以 tcpdump 看到 checksum mismatch 与固定 bit-clear。

## 本轮修复

修改文件：

- `software/firemarshal/boards/firechip/drivers/icenet-driver/icenet.c`

修复内容：

- 引入 `linux/dma-mapping.h`。
- send/recv completion queue entry 记录每个 skb 的 DMA address、length、segment 类型与 segment 数量。
- TX linear data 使用 `dma_map_single(..., DMA_TO_DEVICE)`。
- TX skb frags 使用 `skb_frag_dma_map(..., DMA_TO_DEVICE)`。
- TX completion 中按 segment 调用 `dma_unmap_single` 或 `dma_unmap_page`。
- RX buffer 发布前使用 `dma_map_single(..., DMA_FROM_DEVICE)`。
- RX completion 中先 `dma_unmap_single(..., DMA_FROM_DEVICE)`，再 `skb_put` / `skb_pull` / `netif_receive_skb`。
- TX 改成两阶段提交：先 map 完所有 segment，全部成功后才写 `ICENET_SEND_REQ`，避免某个 frag map 失败时已经向硬件提交半个包。
- checksum offload disabled 版本临时关闭 `NETIF_F_SG`，减少下一轮验证变量。
