## Packet capture result

Passive tcpdump on run-host `tap0` captured the TCP handshake attempt:

- host `172.16.0.1:39818` sends SYN to guest `172.16.0.2:2345`;
- guest replies with SYN-ACK;
- guest SYN-ACK TCP checksum is bad;
- host never ACKs the SYN-ACK and retransmits SYN until timeout.

Concrete first two guest SYN-ACKs:

```text
172.16.0.2.2345 > 172.16.0.1.39818: Flags [S.], cksum 0xeb88 (incorrect -> 0xeb90)
172.16.0.2.2345 > 172.16.0.1.39818: Flags [S.], cksum 0xeb86 (incorrect -> 0xeb8e)
```

The tap neighbor state was correct in this run:

```text
172.16.0.2 lladdr 00:12:6d:00:00:02 STALE
```

This distinguishes the current failure from the earlier run that learned a wrong ARP payload MAC.

## Switch evidence

The bad SYN-ACK checksum is already present when the packet is received from the target side:

```text
SWITCH DEBUG ShmemPort recv_flit port=0 event=7 sample=6 token=6 data=0x000088eb707c12a0 last=0
SWITCH DEBUG BasePort input_packet_flit port=0 event=5 idx=6 data=0x000088eb707c12a0
SWITCH DEBUG SSHPort tap_send_bytes port=1 event=5 off=48 bytes=7c 70 eb 88 00 00 ...
```

The second SYN-ACK repeats the same pattern:

```text
SWITCH DEBUG ShmemPort recv_flit port=0 event=8 sample=6 token=6 data=0x000086eb707c12a0 last=0
SWITCH DEBUG SSHPort tap_send_bytes port=1 event=6 off=48 bytes=7c 70 eb 86 00 00 ...
```

`SSHPort` is not introducing the checksum corruption; it forwards the bytes already present in the target-to-host frame.

## Interpretation

Status: **old AGFI still fails before GDB protocol due to NIC transport checksum corruption**.

The shmem empty-marker clearing experiment did not restore old AGFI `gdbserver` functionality. It appears to have improved ARP neighbor correctness in this one run, but the actual blocker remains target-to-host TCP checksum corruption before or at the SimpleNIC target-to-host packet generation / host-driver transfer boundary.

This means the current repository still has a software/runtime regression even when using the previously passing AGFI. Do not attribute the current failure to new hardware until this old-AGFI control passes again.
