## Debug Rationale

Existing logs can distinguish the earlier cycle-0 deadlock and several
ready/valid masks, but a later failure could still require answering a more
precise question:

```text
host switch produced packet
-> CPU-managed from-host stream accepted it?
-> bigtoken adapter emitted HostToNICToken?
-> htnt_queue captured/dequeued payload?
-> target nicIn actually fired payload?
-> target nicOut emitted payload?
-> ntht_queue and PCIE-to-host path returned it?
```

If any one of these stages stops, the next FPGA failure scene should identify
the deepest reached milestone without another observability-only rebuild.

## Added Observation Surface

The new CSR surface records:

- Chain progress bitmasks and last progress cycle.
- Continuous blocked streak and maximum blocked streak.
- Sticky ever masks for ready/valid/fire/block on both directions.
- Last blocked masks and compact queue/adapter snapshots.
- First/last from-host and to-host blocked edge snapshots.
- Payload/empty counters across `htnt`, target `nicIn`, `ntht`, and PCIE-out.
- Last cycle/data/meta snapshots for `htnt`, target `nicIn`/`nicOut`, and
  `ntht`.
- First milestone cycles for the main payload path.

The marker `minobs_build_marker` is now `0x05040001` for builds that contain
this expanded observation surface.
