## 分析

### 1. watchdog 之前确实存在误杀窗口

- 旧脚本没有把 `guest_checkpoint_log` 的增长算作 progress
- 当前 run 的后继路径恰好大量活动发生在：
  - 固定张量 DMA checkpoint
  - `before-build-stage-task` 之后的 build 路径
- 因此旧 watchdog 可能在 guest 仍然前进时，
  只因为 sparse 主日志暂时不增长而误杀

### 2. stage0 fixed tensor 每个 subbatch 重装是当前编排语义

- 从 `ours2` 编排文件确认：
  - fixed tensor：
    `1000000`
    和
    `1000001`
  - `tensorUseLazyFetch: [0, 0, 0, 0]`
- 所以当前 runtime 在 `stage_prepare_exec_views` 内反复重装固定页，
  是符合当前 artifact 的；它未必是 bug，但必须被正确观测

### 3. 这轮改动的目的不是绕过语义，而是把真实前沿暴露出来

- watchdog 改动不改变 runtime 功能语义
- `stage-exec-views` / `stage-fixed-load-sparse` 仅增加极少量文件日志
- 这两类改动的目标是区分：
  - 真死锁
  - checkpoint-only progress
  - build-stage 内部新的功能性卡点
