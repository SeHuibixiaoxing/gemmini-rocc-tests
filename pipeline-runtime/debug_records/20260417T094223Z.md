## 新观察

### 1. 构镜失败原因已经被精确定位到 workload JSON 语义错误
- `image-closure` 中的 FireMarshal build 失败日志明确报：
  - `ValueError: Run script .../workload/firesim-start-trigger not found.`
- 对应 tmux pane：
  - `/home/ubuntu/chipyard/tmp/firemarshal-tmux/pairdummy-sbus128-tracerv-inst-build-20260417-093903.pane.log`

### 2. `run` 不是 shell 片段，而是 `script + args`
- `software/firemarshal/wlutil/config.py`
  的 `RunSpec.fromString()` 直接把字符串按空格切分，
  并把第一个 token 当成 workload 目录下的脚本路径：
  - `script=(baseDir / scriptParts[0]).resolve()`
- `software/firemarshal/wlutil/build.py`
  在 `runSpec.command is None` 时会检查该脚本路径必须存在。
- 因此：
  - `"run" : "firesim-start-trigger && ..."`
  会被 FireMarshal 解释成
    `script = <workload-dir>/firesim-start-trigger`
  - 而不是 shell 执行 `firesim-start-trigger && ...`

### 3. 真正支持 shell 片段的是 `command`
- `software/firemarshal/docs/source/workloadConfig.rst`
  明确区分：
  - `run`: script or script+args
  - `command`: run-from-root shell command
- `software/firemarshal/docs/source/internal/Build.rst`
  说明 `command` 会先被转换成生成的 run script，再进入 distro boot-script 流程。
- 同一 workload 子树里已有现成先例：
  - 多个 `uartprobe` workload 使用
    `"command" : "ENV=... /root/.../script.sh"`

### 4. guest 内真正可调用的 runtime wrapper 路径已经确认
- `host-init.sh` 会把：
  - `run_rerocc_pipeline_runtime_bertmini_fileonly_sync_capture.sh`
  复制到 guest 的：
  - `/root/rerocc-linux-tests/run_rerocc_pipeline_runtime_bertmini_fileonly_sync_capture.sh`
- `workload/overlay/root/rerocc-linux-tests/`
  目录下也已存在该文件。
- 因而 instruction-trigger workload 最小、正确的表达应当是：
  - 用 `command`
  - 直接调用 guest 内绝对路径
  - 在其前后包 `/usr/bin/firesim-start-trigger` / `/usr/bin/firesim-end-trigger`

## 修改

  `rerocc-lc-linux-coupleddma-bertmini-pipeline-runtime-batch8-fileonly-sync-pairdummy-tracerv-inst.json`
  从非法的：

  - `"command" : "/usr/bin/firesim-start-trigger && /root/rerocc-linux-tests/run_rerocc_pipeline_runtime_bertmini_fileonly_sync_capture.sh --batch 8 && /usr/bin/firesim-end-trigger"`

## 分析
- 这个 blocker 本质上不是 trace 失败，也不是 guest 里缺 trigger 工具。
- 它是 FireMarshal workload 语义层的问题：
  - 我们把 shell 片段误塞进了 `run`；
  - FireMarshal 按 `run script` 规则解析后，自然会去 host workload 目录找 `firesim-start-trigger`。
- 修成 `command` 后：
  - 仍保留 instruction-trigger 语义；
  - 不需要改 canonical baseline；
  - 不需要新增 guest overlay 文件；
  - 也不需要再猜 trigger 工具路径。
