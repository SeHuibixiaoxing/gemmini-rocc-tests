因此，当前最硬的 old/new 退化链是：

```text
04-30 bit-clear 失败
  -> 加 target->host payload snapshot
  -> 04-30/05-01 旧 AGFI remote gdb 跑通
  -> 05-02 归位时裁掉 snapshot
  -> 05-02 新 AGFI 又复现 bit-clear
```

这不能证明 snapshot 本身是“功能修复”，但它证明：移除这批 snapshot 后构建出的硬件
不再等价于已通过硬件。考虑到这些 snapshot 给关键 payload 信号提供了寄存/keep/观测负载，
它们可能改变综合优化、retiming 或物理实现，对当前 F2 target->host payload integrity
有实际影响。既然它们是旧通过硬件的一部分，当前修复必须恢复它们，而不是继续回退到
04-26 的中间态。

## 排除的误回退方向

### 不应把 `fromHostValidDrive` 回退到 04-26 中间态

`20260426T170527Z.md` 曾记录：

```scala
fromHostValidDrive = htnt_queue.io.deq.valid
```

但 04-30 后续已经演进到 self-cleaning no-packet 语义，旧通过 AGFI 生成 RTL 中明确是：

```verilog
assign hPort_nicIn_valid = 1'h1;
assign hPort_nicIn_bits_valid = fromHostCurrentPayloadValid;
assign htnt_queue_io_deq_ready = fromHostEmptyTokenAvailable | fromHostPayloadCapture;
assign ntht_queue_io_enq_valid = hPort_nicOut_valid & hPort_nicOut_bits_valid;
```

当前源码和 05-02 失败生成物在这些真正的数据 ready/valid 赋值上与旧通过版一致。
因此 `fromHostValidDrive = true.B` 不是这次新退化的原因，不能按 04-26 中间记录回退。

### `targetCycleReady` debug 统计差异不是 payload 数据通路修复点

旧通过生成物里 `targetCycleReady` 被优化成：

```verilog
wire targetCycleReady = toHostReadyDrive & hPort_nicIn_ready;
```

当前生成物为：

```verilog
wire targetCycleReady = toHostReadyDrive & fromHostAllReady;
```

其中 `fromHostAllReady` 包含 `macAddr/rlimit/pauser.ready`。该信号当前只用于 debug
计数和 blocker 统计，不反向驱动 `hPort.nicOut.ready` / `hPort.nicIn.valid` /
`ntht_queue.io.enq.valid` / `htnt_queue.io.deq.ready` 这些数据通路提交信号。
它不能解释固定 payload byte 的 bit-clear。

## 当前已完成修复

`20260502T233311Z.md` 已完成两项回退/恢复：

1. 恢复 04-30 通过版中存在的 target->host payload snapshot，并扩展 first16：
   - `bigtoken_current_slot_data`
   - `bigtoken_last_latched_word*`

   - `to_host_hist_data*`
   - `to_host_first_*`
   - `nicbig_ntht_first_*`
   - `nicbig_pcie_first_*`

2. 回退 F2 PCIS 512->64 bridge 写通道 `s_axi_wready` 到旧通过语义：

```systemverilog
s_axi_wready = (wr_state == WR_COLLECT) && !wr_wbuf_valid &&
               (wr_aw_active || wr_aw_fire);
```

PCIS W-before-AW 更偏 host->target/OCL 写通道，不是 target->host payload bit-clear 的直接证据；
但它是 04-30 通过 RTL 与 05-02 失败 RTL 之间明确的功能语义差异，已经回退。
