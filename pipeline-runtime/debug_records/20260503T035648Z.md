## 本轮新增钉证

在 `20260503T032845Z.md` 的回退基础上，继续把当前生成 RTL 与 04-30 通过版逐项比较。
发现上一轮仍留下一个 debug/observability 形态差异：

旧通过版生成 RTL：

```verilog
wire targetCycleReady = toHostReadyDrive & hPort_nicIn_ready;
wire targetBlockedFromHostChannels = htnt_queue_io_deq_valid & _fromHostGroupBlocked_T;
assign crFile_io_mcr_read_17_bits = {{31'd0}, hPort_nicIn_valid};
assign crFile_io_mcr_read_18_bits = {{31'd0}, hPort_nicIn_ready};
```

上一轮本地生成物一度变成：

```verilog
wire targetCycleReady = toHostReadyDrive & fromHostAllReady;
wire targetBlockedFromHostChannels = ~fromHostAllReady;
assign crFile_io_mcr_read_17_bits = {{31'd0}, fromHostChannelValid};
assign crFile_io_mcr_read_18_bits = {{31'd0}, fromHostAllReady};
```

其中 `fromHostAllReady` 把 `macAddr/rlimit/pauser.ready` 聚合进了 SimpleNIC 的
`hport_from_host_ready` / `targetCycleReady` debug 面。该差异不反向驱动
`hPort.nicIn.valid`、`hPort.nicOut.ready`、`ntht_queue.io.enq.valid` 或
`htnt_queue.io.deq.ready`，但它不是 04-30 通过版的硬件形态。考虑到当前问题对
debug fanout / payload snapshot 这类综合形态非常敏感，本轮把它也归位。

## 当前结论

这次不是在同一个点转圈，而是进一步把“新 bitstream 跑不通”的回归空间压缩：

1. 05-02 归位删掉旧通过版 payload snapshot，是 `agfi-032d10150efc1d4ec` 复现
   target->host corruption 的最硬 old/new 差异。
2. 上一轮补 first16 / PCIS write-order debug 过头，导致构建输入不再是干净的旧通过形态。
3. 本轮继续去掉最后的 `fromHostAllReady/configChannelReady` debug 聚合差异，使
   SimpleNIC 数据通路 marker、payload snapshot surface、target-cycle debug 关键表达式、
   PCIS bridge 形态都回到 04-30 通过版可背书的形态。
