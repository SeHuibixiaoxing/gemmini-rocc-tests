## 证据

本轮 run host：`i-04244d7bce33e2231` / `192.168.1.194`。

远端 driver freshness gate 通过：`FireSim-f2` 内含：

- `+simplenic-empty-switch-poll-interval`
- `empty_rounds_skipped_switch`

Guest boot 走到完整 Linux + IceNet + rootfs + network：

- `Registered IceNet NIC 00:12:6d:00:00:02`
- `Mounting /dev/iceblk as root device`
- `Starting network: OK`
- `[gdbserver] phase=prelaunch net_dev=eth0 guest_ipv4=172.16.0.2 endpoint=172.16.0.2:2345 pid=0`

Run host 到 guest NIC 双向基础连通性成立：

- `ping 172.16.0.2` 成功，2/2 replies
- `ip neigh show dev tap0` 解析到 `172.16.0.2 lladdr 00:12:6d:00:00:02 REACHABLE`

真实 cross-gdb attach 成功，不是 `nc/telnet` 探端口：

```text
(gdb) target remote :32345
0x0000000000010420 in _start ()
Program stopped at 0x10420.
It stopped with signal SIGTRAP, Trace/breakpoint trap.
#0  0x0000000000010420 in _start ()
```

第二次 reconnect 返回：

```text
Remote communication error.  Target disconnected: Connection reset by peer.
```

这与 workload 使用 `gdbserver --once` 一致：第一次 attach 消耗了唯一连接会话。

## 结论

1. 之前“进不了 boot / IceNet / 网络”的 blocker 已被推进过去。
2. SimpleNIC host-driver empty round throttling 修复生效：此前 gdb attach host `FireSim-f2` 常见热点是 `simplenic_t::tick -> clear_bigtoken_headers`；本轮 early boot 采样已转为 `uart_t::tick -> simif_f2_t::read -> fpga_pci_peek`，说明最明显的 SimpleNIC 空轮询热点已被压下。
3. NIC 双向通信已经有确定证据：guest IP 可 ping，ARP 正确，gdb remote TCP 能建立。
4. 当前还需要补一轮完整 gdb 操作验证：同一次 `--once` 会话内执行 `break main -> continue -> bt/info registers`。上一轮第一次 attach 为了取证使用了 `detach`，因此 `--once` 会话被消耗，不能再复用。
