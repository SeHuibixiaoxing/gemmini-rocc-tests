# Debug Record 20260429T092230Z

调试类别：gdbserver

## 本轮目标

按用户要求，把当前 NIC 调试结论继续归档，并验证另一条更快的测试路线：

1. 能否构建一个简单 baremetal 程序来拆分/复现 NIC 问题。
2. 本机 FireSim metasim 跑 baremetal 是否必须启动 Linux/rootfs。

## 当前主结论

最新 F2 `singlecore + NIC + gdbserver smoke` 的 host->target 失败点仍然指向
F2 shell PCIS 宽度桥接，而不是 Linux、gdbserver 或 SimpleNIC host C++
完全未收到包：

- F2 现场中 C++ / switch 已经收到 host->target 包，`simplenic_t::push()`
  返回成功。
- F2 RTL 侧 `pcie_in` / `bigtoken_accept_count` 增长，但
  `bigtoken_payload_emit_count=0`，`from_host_payload_capture_count64=0`。
- 当前 F2 shell 顶层仍是 512-bit PCIS `wdata/wstrb`，而生成出的
  `F1Shim.io_pcis_w_bits_data/strb` 已经是 64-bit/8-bit。
- F2 顶层仍直接把 512-bit shell 信号连到 64-bit generated shim，Verilog
  会截低 64-bit lane。若 `fpga_pci_poke64()` 对应的有效 64-bit 数据落在
  512-bit beat 的非低 lane，RTL 就只看到空/错数据。

因此当前最硬根因仍是：

```text
F2 shell PCIS 512-bit write beat
  -> direct connect / truncate
generated F1Shim 64-bit CPUManagedAXI4
  -> BigTokenToNICTokenAdapter 无法识别 payload header
```

`CPUManagedStreamEngine` AW/W 独立握手问题仍是需要修的次级风险，但它不是
解释当前 F2 `payload_emit=0` 的最直接证据链。

## Baremetal / Metasim 结论

FireSim-managed local metasim 可以跑 baremetal，不需要启动 Linux，也不需要

- workload 可以使用 `common_rootfs: null`。

## 对原 F2 Bug 的意义

本轮 baremetal/metasim 没有复现 F2 的同一个 host->target 失败形态。相反，
它提供了一个关键对照：

- 在不经过 F2 shell 的 local metasim 中，host->target payload 能被
  `BigTokenToNICTokenAdapter` 识别，`payload_emit` 和
  `from_host_stage.capture_count` 会增长，baremetal 程序能收到 ARP。
- 在 F2 中，C++ 已 push 成功，但 `payload_emit_count=0`、
  `from_host_payload_capture_count64=0`。

因此 F2 问题不应继续优先怀疑 Linux、gdbserver、baremetal 程序、tap 配置，
也不应优先怀疑 SimpleNICBridge 的 bigtoken adapter 在所有后端都失效。
更确定的方向仍是 F2 shell PCIS 512-bit 到 generated F1Shim 64-bit 的桥接。

## 后续建议

1. 修 F2 `cl_firesim.sv` 顶层 PCIS 512->64 lane select / downsizer，至少记录
   `awaddr/awsize/wstrb/wdata[8 lanes]/selected_lane/selected_data`。
2. 同步修 `CPUManagedStreamEngine` AW/W 独立握手风险，避免修完 F2 顶层后撞到
   标准 AXI 写通道问题。
3. local metasim 继续作为快速回归：
   - host->target ARP 是否仍能到达 `pingd`；
   - target->host 的 `pcie_out` / switch / tap 出口另列为 metasim-only 待查项。
4. 如果后续要让 baremetal ping 完整成功，需要继续查
   `pcie_out -> C++ SimpleNICBridge -> switch shared memory -> tap0` 这条出口链路。
