## 分析

### 当前结论

这轮最小 `1 CPU + NIC` local metasim 已经证明：

- 当前源码下的 networked topology + `SimpleNIC` 基础路径是能跑通的
- 之前那条“刚进 `Commencing simulation.` 就死于 `simplenic_t::push()`”
  的最早期失败，不再是当前源码在 generic metasim 路径上的稳定现象

也就是说，上一轮对 `SimpleNICBridge.scala` 的“同拍 token 推进”修复，
至少通过了这条最小 smoke 的实跑验证。

### 这轮没有证明什么

这轮还不能直接推出：

- 现有 FPGA AGFI 上的问题已经自动消失
- `cfg32 + NIC + gdbserver + Linux` 全链路已经正确
- pipeline runtime 主线问题已经解决

原因是：

- 本轮使用的是本机当前源码重新构建出的 metasim driver
- 不是旧 FPGA AGFI
- 也没有覆盖 Linux/gdbserver/bertmini/pipeline-runtime 路径

### 对根因范围的收缩

和上一轮相比，现在可以把怀疑范围明显缩小：

1. 不是“只要带 NIC 就必然在 `simplenic` 上立刻炸”
2. 不是最小 networked topology 本身就坏
3. 更像是以下几类之一：
   - 旧 FPGA bitstream / driver 没带上这次 `SimpleNICBridge` 修复
   - F2 特有 host path 与 metasim path 仍有差异
   - Linux/gdbserver/full guest workload 引入了额外 NIC 压力或时序
