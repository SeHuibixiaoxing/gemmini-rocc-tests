## 当前最可信工作假设

1. `set_src` 并不是因为 DMA 数据面 backlog 卡住。
2. 它更可能是在进入 CoupledDMA 之前，
   因为 ReRoCC credit / ack / arbiter 的时序问题被卡住。
3. 额外 monitor 指令会改变绝对 stall token
   （之前是 `1032`，本轮变成 `726`），
   但不会改变“卡在 `set_src` 边界”这个相位，
   这更像时序敏感问题，而不是固定地址或固定 token 的语义错误。
