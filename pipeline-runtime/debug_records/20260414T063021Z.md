## 新静态结论

- 当前 `tok=726` 证据说明：
  `set_src` stall 更像 ReRoCC 前端接受问题，
  而不是 DMA monitor 可见的数据面 backlog。
- 继续在 `set_src` 前插入 5 条 `read_monitor` 指令会显著放大 credit / ack 路径压力，
  这会继续改变绝对 stall token，
  不适合作为下一轮默认 probe。
- `src/prt_dma.c` 里已经有现成低扰动观测基础：
  - RR CSR 读取
  - token 持有的 `rr_cfg_id / rr_manager_id / rr_opcode_id`
- 硬件侧还存在可直接利用的 manager 控制寄存器：
  - `mgr_busy`
  - `rocc_busy`
  地址由 `ReRoCCManagerControlBase + mgrId * ReRoCCManagerControlSize`
  固定映射，
  可通过 guest `/dev/mem` 读取。
