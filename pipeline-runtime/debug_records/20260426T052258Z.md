## 新静态结论

上一轮修补把 `fromHostValidDrive` 写成了 `htnt_queue.io.deq.valid && fromHostChannelReady`。这对 FireSim `ChannelizedHostPortIO.OutputChannel` 不成立：

- host->target 的 `OutputChannel` 在 FAME1 中是 target input channel。
- FAME1 只会在整个 target cycle 可以完成时同时拉高这些 channel 的 `ready`。
- 因此 bridge 端的 `valid` 不能等待 `ready`；否则会形成 ready/valid 互等。

本轮日志正好吻合这一点：

- 多次看到 `fromHostTokenAvailable=1`，但 `fromHostValidDrive=0`。
- `TARGETCYCLE DEBUG` 中反复出现 `wire_input_missing_valid[5] ep_3_nicInValid`。
- 这解释了为什么 guest boot 可以慢慢推进，但 NIC input token 链路经常被 host->target valid 抑住。
