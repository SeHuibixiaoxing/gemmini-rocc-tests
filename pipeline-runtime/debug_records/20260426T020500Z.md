## 新静态结论

`ChannelizedHostPortIO` 每个 leaf channel 都是独立 `Decoupled` 通道。当前 `SimpleNICBridgeModule` 虽然把 NIC 拆成了 leaf channels，但仍存在一个同步语义漏洞：

- host-to-target 方向：`nic.in.valid/data/keep/last`、`macAddr`、`rlimit.*`、`pauser.*` 的 `valid` 会在 `htnt_queue.io.deq.valid` 时持续拉高。
- bridge 只在 `fromHostFire` 时推进 `htnt_queue.io.deq.ready`，但没有阻止已经 ready 的单个 leaf channel 提前 fire。
- target-to-host 方向：`nic.out.valid/data/keep/last` 的 `ready` 原来直接由 `ntht_queue.io.enq.ready` 驱动，也允许某些输出 leaf 在整组未齐时提前 fire。

这会让独立 leaf channel 之间出现 token skew：某些字段先接收重复 token，另一些字段滞后。NIC 的 `valid/data/keep/last` 与 sideband 配置一旦错位，host 注入的网络帧可能到不了 guest NIC 的正确接收路径。这个问题是 NIC channelized bridge 特有的；UART/TSI 没有这组多字段 leaf 同步问题。

## 本轮修复方向

把 NIC token 的两组 leaf channel 显式同步：

- `toHostFire = toHostChannelValid && ntht_queue.io.enq.ready`
- `hPort.nicOut*.ready := toHostFire`
- `ntht_queue.io.enq.valid := toHostFire`
- `fromHostFire = htnt_queue.io.deq.valid && fromHostChannelReady`
- `hPort.nicIn*/mac/rlimit/pauser.valid := fromHostFire`
- `htnt_queue.io.deq.ready := fromHostFire`

这样每个 NIC token group 内的所有 leaf channel 只能全组同周期 fire，不能部分 fire。
