## 关键静态结论

### 1. “第二次导出 tensor=2” 不是无语义重复
- `model.layers.yaml` 中 layer 3 (`index: 3`) 的 `tensorIds: [1000006, 2, 3, 6]`
- 同一 slot 上同时存在：
  - `address[1] = 132096`
  - `address2[1] = 8659968`
- 因此 `tensor=2` 本来就存在两个 alias 目标。
- `copy_tensor_pages_to_model_aliases()` 的当前实现也是按：
  - `address`
  - `address2`
  两类目标分别导出，只按“目标地址 + 大小”去重，而不是按 `tensor_id` 去重。
- 结论：本轮看到的两次 `dma-export-host tensor=2` 与模型 alias 语义一致，不能简单视为错误重复拷贝。

### 2. 当前冻结更精确地落在 `copy_tensor_pages_to_model_aliases()` 的第二个 alias 目标导出期间
- 路径为：
  - `worker -> sync_stage_export_aliases()`
  - `copy_tensor_pages_to_model_aliases()`
  - `copy_tensor_pages_to_model_alias_target()`
  - `prt_dma_copy_spm_pages_to_dram()`
- 第一目标导出已完整通过。
- 第二目标导出已通过到 `page=48/64` 附近，但尚未完成整个 alias target。

### 3. 主日志半行并不等价于“必然卡在日志函数内部”
- `include/prt_progress.h` 里的 `prt_write_fd_all_impl()` 一旦 `write()` 只接受了部分字节，就直接返回，不会补写剩余部分。
- 因此尾部半行只说明“最后一次写入发生了短写”，不能单独拿来证明程序死在 `PRT_PROGRESS_LOG(...)`。
- 但它仍然说明：最后一次对外可见事件发生在第二个 alias target 的 `page=48/64 end` 邻近位置。

### 4. 当前 probe 粒度不足以区分“卡在 page=49..55 的哪一页”
- `dma_should_sparse_export_page_probe()` 当前只在这些页输出：
  - `page=0`
  - `page % 8 == 0`
  - `last page`
- 所以停在 `page=48/64` 之后，并不意味着一定卡在 `page=56`。
- 实际可能卡在：
