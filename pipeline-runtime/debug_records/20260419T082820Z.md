- `tracerv_metasim_bringup_plan_20260418.md`
- 多轮 `debug_records/`
- 多轮 `change_records/`

但这些更多是 run-by-run 历史与阶段计划，
还不是一份可直接复用的 SOP。

### 2. 这轮已经稳定下来的经验足够升格成 SOP

最关键的稳定结论有三条：

1. `TracerV` 是否跑通，
   先看 host 是否发生过 nonzero pull，
   不要先盯 `TRACEFILE-C*`
2. `selector=3` 先在最小样例上验证，
   再回到长 workload
3. 若 marker 放在超长 prefill 之后，
   `TRACEFILE-C* == 0` 不等于 `TracerV` 坏了

### 3. 这份 SOP 应归入 `docs/testing/`

依据 `document_workflow.md`：

- debug SOP / probe 策略变化
  应放在 `docs/testing/`
- 并同步更新 `docs/testing/observability.md`
