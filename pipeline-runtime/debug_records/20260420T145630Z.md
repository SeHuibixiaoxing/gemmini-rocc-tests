## 新观察

### 1. 这轮已经足够证明：guest 是真实 stall，不是 watchdog 误杀

watchdog 记录显示：

- `guest_sparse`
  从
  `1011`
  推进到
  `198085 -> 240481 -> 323227`
- plateau 之后 heartbeat 继续从
  `425`
  增长到
  `1912`
- plateau 时间至少持续到
  `idle=1063s hb_idle=0s`

因此这轮不是 host 提前回收；
guest 程序在 heartbeat 仍前进的同时，
把 `guest_sparse` 稳定卡在
`323227`
上。

### 2. fresh binary 的 live guest 文件在两次抓取之间完全同尺度

`20260420T143126Z` 与 `20260420T144843Z`
两次 capture 中：

- `bertmini-batch8.log = 323227`
- `bertmini-batch8.breadcrumb.bin = 7272`
- `bertmini-batch8.runner-proc.stage = 9265`
- `bertmini-batch8.trigger.log = 0`
- `status` 仍是 `state=running`

这说明 run 已进入稳定 plateau；
不是“只是还没来得及继续滚动”。

### 3. fresh rerun 明确带着 `v2p` probes，但当前 ring 里仍然没有 `before_v2p/after_v2p`

这轮不是旧 binary：

- local / remote freshness 已通过
- runtime binary hash 与本地构建一致
- 这轮之前已经落下
  `dma_page_before_v2p / dma_page_after_v2p`

但 fresh rerun 的 decoded breadcrumb 结果仍然是：

- `last_slot`：
  `seg=0 gstage=0 lstage=0 sb=3 tensor=2 page=28 phase=dma_page_after_accounting`
- `--all`
  当前 populated ring 中，
  没有
  `dma_page_before_v2p`
  也没有
  `dma_page_after_v2p`

因此这轮新证据已经把首个冻结点收窄为：

- `page28 after_accounting`
  之后
- 且早于
  `page29 before_v2p`

## 本轮结论

- 这轮 fresh rerun 已经充分证明：
  1. `host-watchdog` 不是当前主线 blocker
  2. 当前 guest 是真实 stall
  3. 当前首个冻结点**早于**
     `before_v2p(page29)`
- 因而之前把
  `prt_host_virt_to_phys()`
