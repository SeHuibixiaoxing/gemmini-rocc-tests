# 8BP single-core NIC AGFI 与当前 driver 不一致导致 infrasetup 超时

日期：2026-05-01T16:17:52Z

## 本轮对象

刚完成的 single-core Rocket + NIC + no TraceIO + 8 hardware breakpoints + 30MHz
构建：

- tmux：`build-8bp-timing-pcisfix2-20260501T123100Z`
- AGFI：`agfi-054e7cc532edd4698`
- AFI：`afi-0f3753d3a0dca133d`
- FireSim build exitcode：`0`
- Vivado 结果：AGFI 创建成功，但 post-route DCP 报 timing failure

重要限制：该 AGFI 的远端 Verilog 快照早于 `2026-05-01 14:14-14:18 UTC`
新增的 NIC adapter-stage first16 观测点。

`launchrunfarm` 成功。`infrasetup` 失败在 driver readiness preflight：

```text
timeout --kill-after=5s 30s sudo ./FireSim-f2 ... +check-fingerprint
return code 124
FireSim driver readiness preflight failed for slot 0 after 3 attempts.
```

该失败发生在 workload/Linux/gdbserver 之前。

## 直接证据

远端 build host 的该 AGFI Verilog 快照已确认不含最新观测点：

```text
nicbig_ntht_first_packet_seq: no match
nicbig_pcie_first_packet_seq: no match
to_host_first_packet_seq: no match
```

但 `infrasetup` 实际部署到 F2 的 driver 来自当前本地生成物，已经包含最新字段。
对 `192.168.1.13:/home/ubuntu/sim_slot_0/FireSim-f2` 执行 `strings` 可见：

```text
SIMPLENIC TX FIRST16 [%s] stage=%s ...
nicbig_ntht
nicbig_pcie
nicbig_ntht_first_data...
nicbig_pcie_first_data...
```

本地当前 `FireSim-generated.const.h` 与 `FireSim-generated.sv` 也包含：

```text
nicbig_ntht_first_packet_seq_*
nicbig_pcie_first_packet_seq_*
```

## 结论

这次 `infrasetup` timeout 不是 gdbserver 功能测试失败，也不是新的 guest/NIC
运行期证据。它是一次 driver/AGFI freshness 错配：

- AGFI：旧 RTL，不含最新 first16 MMIO register map；
- driver：新 RTL collateral，含新增 register map 和 host dump 字符串。

FireSim `+check-fingerprint` 在这种错配下无法作为硬件功能结论使用。继续用这个
AGFI 做 gdbserver/NIC 测试没有意义，除非重新生成与旧 AGFI 完全匹配的旧 driver。
当前更合理路径是构建一颗包含最新 first16 观测点的新 AGFI，并在启动远端 Vivado 后
再次核对远端 `FireSim-generated.sv` 的字段。
