  - `from_cpu_stream` push blocked，`space_available=0`。
  - HTNT 队头是空 token：`data_in_valid=0`、`keep=0xff`。
  - `hPort.nicOut` 也在输出空 token，队列满后反压。
- 因此当前 remote gdb 失败不是 gdbserver/workload 问题，而是 target 进入 boot 之前 SimpleNIC bridge 空 token 造成双向队列死锁。

## 根因判断

- host driver 在 target 没有输出时会启动一个 empty round，用于让 switch 处理 tap0 输入。
- 最新硬件把 `nicIn` 与 `macAddr/rlimit/pauser` 作为 channelized host port，并且让空 HTNT token 也等待 target input channel ready。
- 早期 boot 前 target 还没有产生有效 NIC payload，host->target 与 target->host 两边都是空 token。
- 空 token 被当作必须握手的真实 token 后：
  - host->target 空 token 塞满 from-cpu stream / HTNT；
  - target->host 空 token 塞满 NTHT / to-cpu stream；
  - host driver 又在 pending push 状态下不继续 pull；
  - 形成双向 backpressure，Linux boot 无法推进。

## 修正方向

- 静态配置 `macAddr/rlimit/pauser` 每个 target cycle 都 valid，不再依赖 HTNT token。
- host->target 空 token 直接丢弃，不等待 target NIC input ready。
- target->host 空 token 在 NTHT 队列满时旁路丢弃；真实 payload 仍严格等待队列 ready。
- 增加 `to_host_empty_bypass`、`to_host_empty_enqueue`、`from_host_empty_drop`、payload blocked 等可综合计数器，下一轮现场可直接验证修正是否生效。
