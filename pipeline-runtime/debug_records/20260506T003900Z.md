# 2026-05-06 00:39:00 UTC - cfg32 batch gdbserver triage helper

## Goal

Prepare a reproducible first-attach path for the future cfg32 NIC gdbserver run
while the noTrace bitstream is still building. The existing
`run_pairdummy_cfg32_gdbserver_first_triage.sh` is useful for interactive GDB,
but the first validation on a fresh AGFI should leave deterministic logs.

## Change

Added:

```text
pipeline-runtime/scripts/run_pairdummy_cfg32_gdbserver_expect_triage.sh
```

The helper:

- accepts `<run-host-private-ip> <guest-ip-or-endpoint> [local-port]`;
- opens an SSH local-forward through the FireSim run host;
- uses GDB, not `nc` or `telnet`, as the first TCP client to `gdbserver --once`;
- records a transcript under
  `tmp/firesim-aws-f2/gdbserver-tests/pairdummy-cfg32-expect-*`;
- captures initial threads, backtraces, registers, and disassembly;
- inserts software breakpoints at the current pipeline-runtime triage symbols;
- continues to the first breakpoint and records stack/thread/register state;
- disables breakpoints, sends Ctrl-C, records the recovered state, and detaches.

Updated:

```text
pipeline-runtime/docs/testing/gdbserver_integration_sop.md
```

to prefer the batch/expect helper for first validation evidence and keep the
older helper for explicit interactive sessions.
