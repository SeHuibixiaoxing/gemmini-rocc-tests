## 动态结果

### 1. run host / switch / tap 均已起来

远端 screen：

- `fsim0`
- `switch0`
- `hw_server`
- `virtual_jtag`

`tap0`：

- `UP,LOWER_UP`
- `172.16.0.1/16`
- RX 始终为 0
- TX 持续增长

15B cycles 时：

```text
RX: bytes=0 packets=0
TX: bytes=9860 packets=34
```

pcap 只看到 host 周期广播：

```text
IP 172.16.0.1.1534 > 172.16.255.255.1534: UDP, length 248
```

没有任何 guest -> host 包。

### 2. guest 已进入 OpenSBI / Linux early boot

`uartlog` 中出现：

```text
OpenSBI v1.2
[    0.000000] Linux version 6.6.0-00004-g67bc4513761f ...
```

因此这轮再次确认：这不是 UART/TSI/boot 本身不能工作的问题。

### 3. sync-gated 旧 AGFI 的 ready/valid 互等现场被复现

关键现场反复出现：

```text
from_host_token_available=1
from_host_valid_drive=0
```

例如：

```text
SIMPLENIC DEBUG REGS [...] drives ... from_host_valid_drive=0 from_host_token_available=1 queue_raw htnt(enq_ready=0 deq_valid=1)
```

同时 `chan_from_host_*` 也显示：

- `would_valid=0x7ff`
- 但实际 `valid` 可为 `0x0`
- partial-fire count 仍为 0

这和静态结论吻合：

```text
上一版 sync-gated 修补把 fromHostValidDrive 写成
htnt_queue.io.deq.valid && fromHostChannelReady，
导致 host-to-target valid 等待 target-cycle ready；
FAME1 target-cycle ready 又等待 input valid，形成互等。
```

### 4. 当前 run 没有等到 gdbserver

本轮观察到约 `15.0B` target cycles：

```text
15030389699, 503
```

还没有出现：

- `S99run`
- `[gdbserver] phase=listening`
- guest -> host 网络包

但已经足够证明 NIC 链路当前断在 guest 能回包之前。

## 结论

本轮 preserve rerun 已补齐上一轮未 copyback 的关键现场：

1. run host、switch、tap 都工作，`tap0` 为 `LOWER_UP`。
2. host 侧流量确实进入 tap/switch，pcap 有 host 广播。
3. `tap0 RX=0`，没有 guest 回包。
4. guest 能进 OpenSBI/Linux early boot。
5. `from_host_token_available=1` 但 `from_host_valid_drive=0` 的旧 AGFI
   ready/valid 互等现场被直接复现。

因此，当前正在构建的 `validdrive` bitstream 修复方向仍然成立：

- host-to-target leaf `valid` 必须只由 `htnt_queue.io.deq.valid` 驱动；
- `htnt_queue.io.deq.ready` 仍由 `fromHostValidDrive && fromHostChannelReady`
  控制；
- 验证重点是新 AGFI 中 `from_host_token_available=1` 时
  `from_host_valid_drive=1` 且 `chan_from_host_valid_mask=0x7ff`。
