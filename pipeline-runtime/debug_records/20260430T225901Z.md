## 关键证据

对正在运行的 host driver 进程做 `gdb -batch -p <FireSim-f2-pid>`，采到：

```text
#0  clear_bigtoken_headers(...)
#1  simplenic_t::tick(...)
#2  firesim_top_t::simulation_run(...)
```

这条证据把卡点从“guest Linux 内部卡死”收敛到 host-side SimpleNIC driver 的 empty-round 路径：

- driver 在 relaxed 模式下允许 target->host stream pull 返回 0；
- 旧逻辑每个 empty NIC tick 都会清 `SIMLATENCY_BT=915` 个 bigtoken header；
- 然后发布 empty shmem round 给 software switch；
- 若 peer 仍为空，再执行 `tick_peer_empty_skip_push`，不向 FPGA from-host stream 写空 token；
- FPGA-side bridge 已自生成 no-packet host input token，所以每个 empty round 都唤醒 switch 并清大 buffer 没有必要，反而让 Linux boot 看起来停住。

因此本轮结论不是 RTL 必须修改，而是 host driver 在“无网络包”时工作量过大，导致目标机推进极慢。

修复内容：

1. 新增 host-driver plusarg：

   `+simplenic-empty-switch-poll-interval=<N>`

   语义：target->host 没有 payload 时，不再每个 empty NIC cycle 都发布 empty shmem round 给 switch；每 N 个 empty round poll 一次 switch，用于发现 host TAP 侧新包。

2. 默认值为 `1`，保持旧行为，避免影响其它配置。

3. 当前 gdbserver smoke runtime 设置为：

   `+simplenic-empty-switch-poll-interval=1024`

4. relaxed 模式下，`pcis_read_buf` 只有在可能存在旧 header 时才调用 `clear_bigtoken_headers()`，避免每个 empty pull 都清 915 个 bigtoken header。

5. debug dump 增加 `empty_rounds_skipped_switch` 计数，用于确认节流是否生效。
