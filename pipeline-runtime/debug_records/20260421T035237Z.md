## 本轮新观察

### 1. 现有 selector=3 路线过粗

- 当前 runtime 里真正的 raw instruction marker 只有 worker start/end：
  - `0x00008013`
  - `0x00010013`
- 它们只能回答：
  “worker 大体进入 / 退出没有”
- 它们不能回答：
  `segment3 stage0 tensor6 export`
  这条 DMA/RR 走廊里哪一段指令已经退休

### 2. `segment3 stage0 tensor6` 确实是适合单独下 probe 的目标

- mapping 显示：
  - `segment_idx: 3`
  - local stage 0
  - `exportTensorIdList: [6]`
  - `exportTensorTypeList: [ISOLATE_SPM]`
- runtime 又会在
  `sync_stage_export_aliases()`
  上额外把这份 SPM 数据同步到 model alias
- 因而：
  `tensor 6`
  同时满足
  - 当前 plateau 的静态怀疑中心
  - 与旧 `segment0 tensor2` 不同，不会复用原先的 export 路径

### 3. 共享 RR scope 是当前必须显式观察的点

- 这条 host-copy export 路径不是“每页 acquire/release 一次”
- 实际行为是：
  - 外层一次 `dma_batch_scope_acquire()`
  - 每页内部 `hw_dma_fence()` 与共享 `rr_fence`
  - 批末统一 `dma_batch_scope_release()`
- 因而如果只盯每页 submit/wait，不看批末 release，
  会漏掉一个真正可能阻塞 CPU 的窗口

## 本轮修改

- 在 `prt_dma.c` 中新增了一组 stage/tensor/page 过滤后的 raw markers：
  - `program_begin`
  - `program_post_fence`
  - `program_post_dst`
  - `program_post_src`
  - `wait_before_fence`
  - `wait_after_fence`
  - `wait_before_shared_fence`
  - `wait_after_shared_fence`
  - `batch_release_begin`
  - `batch_release_end`
- 新 marker 只在下面条件同时满足时发射：
  - `stage=0`
  - `tensor=6`
  - `copied==0`
  - 可选 page range：
    `PIPELINE_RUNTIME_DMA_TRACERV_PAGE_START/END`
- 在 `tracerv-inst` workflow 中新增：
  - `PAIRDUMMY_TRACERV_START_INST`
  - `PAIRDUMMY_TRACERV_END_INST`
  用于生成 effective runtime config
- 在 local image freshness 中新增：
  - 新 DMA-window markers 的存在性检查

## 分析

### 为什么这批 marker 比继续堆文本日志更合适

- 它们直接围绕具体退休指令触发，不再依赖 guest 文件日志能否及时刷出
- `selector=3` 可以严格做“命中 / 未命中”二分
- page range 可以先锁历史签名页 `124`，减少噪声

### 为什么先从 `program_post_src -> wait_before_fence` 开始

- 这一对窗口刚好回答：
  “submit 编程段是不是完整退休了”
- 一旦这件事说清楚，下一步就能明确分流到：
  - `hw_dma_fence()`
  - shared `rr_fence`
  - 或批末 `rr_release`
