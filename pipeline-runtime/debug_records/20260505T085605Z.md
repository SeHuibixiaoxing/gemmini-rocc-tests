## Static findings added in this round

### RL_SHIM PCIS tight pins are not new by themselves

The current 2026-05-05 timing-holdfix comparison build has many tight
setup/hold pins under:

```text
WRAPPER/RL_SHIM/DMA_PCIS_AXI_REG_SLC/AXI_REGISTER_SLICE
```

That looked suspicious because the active 0758 route log also points at
`WRAPPER/RL_SHIM/DMA_PCIS_AXI_REG_SLC/...`.

However, the old known-good 2026-04-30 AGFI build also has the same class of
tight pins:

```text
old 2026-04-30 tight_setup_hold_pins.txt lines: 2002
current 2026-05-05 tight_setup_hold_pins.txt lines: 1945
old DMA_PCIS_AXI_REG_SLC tight pins: 1801
current DMA_PCIS_AXI_REG_SLC tight pins: 1827
```

Top prefix counts:

```text
old:
1801 WRAPPER/RL_SHIM/DMA_PCIS_AXI_REG_SLC/AXI_REGISTER_SLICE
42   WRAPPER/RL_SHIM/OCL_REG_SLC/inst
29   WRAPPER/CL/SH_DDR/ddr_stat.CCF_XSDB_REQ

current:
1827 WRAPPER/RL_SHIM/DMA_PCIS_AXI_REG_SLC/AXI_REGISTER_SLICE
42   WRAPPER/RL_SHIM/OCL_REG_SLC/inst
29   WRAPPER/CL/SH_DDR/ddr_stat.CCF_XSDB_REQ
```

Conclusion: RL_SHIM PCIS tight setup/hold pins are a strong timing-pressure
indicator, but not a standalone explanation for the new GDB failure. A passing
AGFI already contained almost the same class of tight pins. The delta to watch
is routed slack/hold behavior, physical placement, Route 35-514 bailout, and
runtime symptoms, not just the presence of this endpoint class.

### Shell PCIS slices may not be sufficient

The current PCIS experiments add one or two register slices at the F2 shell
boundary:

```text
WRAPPER/CL/CL_DMA_PCIS_SLV/AXI4_REG_SLC_PCIS_SLR2
WRAPPER/CL/CL_DMA_PCIS_SLV/AXI4_REG_SLC_PCIS_SLR1
```

The latest active route evidence still names
`WRAPPER/RL_SHIM/DMA_PCIS_AXI_REG_SLC/...` as the tight pin class. This does not
mean the shell slices are harmful, but it does mean they may be cutting a
different segment than the endpoint currently dominating tight setup/hold.

### Old passing AGFI also had violated timing and Route 35-514-like evidence

The old known-good AGFI build's post-route report had violated paths, especially
around DDR ready/reset asynchronous paths. Its Vivado log also contained a
large-hold-violator route event. Since that AGFI passed the GDB smoke matrix,
the decision rule is:

- do not reject a new AGFI solely because post-route timing is violated;
- do collect the exact report and run the GDB smoke if Vivado produces an AGFI;
- do compare runtime failure signatures against old AGFI behavior.

### 8BP is still not on the active path

The active build recipes continue to use:

```text
FireSimRocketNICNoTraceConfig + BaseF2Config
```

They do not use `FireSimRocketNICNoTrace8BPConfig`, and this round did not touch
Rocket `WithNBreakpoints(8)` logic.
