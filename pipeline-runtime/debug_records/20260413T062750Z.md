## DMA Wait Semantics Reconfirmed In Code

- `prt_runtime.c` forces `PRT_DMA_BACKEND_BLOCKING_FENCE` when in blocking debug sync mode.
- `prt_dma.c` backend init selects:
  - `submit = dma_blocking_submit`
  - `wait = dma_blocking_wait`
  - backend name `blocking_fence`
- `prt_dma.c` submit path still acquires/programs a `doneflag` physical address.
- `prt_dma.c` wait path calls `hw_dma_fence()` and then proceeds with the fence/release flow.
- So the correct precise statement is:
  - `doneflag` remains part of DMA completion metadata/programming
  - completion waiting itself is fence-based, not doneflag polling
