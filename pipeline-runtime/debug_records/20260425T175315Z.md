## 文档依据

FireSim `HostPort.scala` 对 legacy `HostPort` 的定义很明确：

- 它把 bridge host 接口建模为单个 input token 和单个 output token。
- 它只适合 tick-like 行为，尤其是不要求 output 组合依赖 input token 的简单 bridge。

`ChannelizedHostPort.scala` 则明确说明：

- `ChannelizedHostPortIO` 用于对 channel 定义做更细粒度控制。
- 对 target 有组合耦合的 bridge，这是需要使用的接口。

FireSim LI-BDN 文档的 `Self-Cleaning` 与 `No Extraneous Dependencies` 规则进一步说明：

- 一个模型不能因为未来外部活动才最终产生已经具备输入条件的输出 token。
- bridge 不能把一个输出 channel 的推进错误依赖到无关 input channel 上。

`Bridges.rst` 对 NIC 的描述也与此一致：NIC driver 在软件 switch 和 bridge module 间批量搬 token，bridge module 应主要负责排队，而不是把所有 NIC leaf channel 再聚合成单个 HostPort lockstep。

## 静态结论

上一轮 FPGA 现场里看到：

```text
BlockDevBridgeModule     to(v=1 r=0)
UARTBridgeModule         to(v=1 r=0)
SimpleNICBridgeModule    to(v=0 r=1) from(v=1 r=0)
```

这不应解释成 UART/TSI/BlockDev 自身有同类 bug。生成后的 FAME target model 只有在 `targetCycleFinishing` 成立时才会推进一个目标周期；只要 NIC from-host sink token 缺失或被错误依赖链挡住，`targetCycleFinishing` 就不成立，其它已经有输出 token 的 bridge 也会表现为 ready=0。

也就是说，UART/BlockDev `to(v=1,r=0)` 是全局 target-cycle 提交被 NIC 拖住后的连带症状，不是当前根因。

旧 `SimpleNICBridge` 使用 `HostPortIO[NICBridgeTargetIO]` 时，`FPGATop.HostPortIOConnectChannels2Port` 会：

- 对所有 toHost channel 的 `valid` 做 AND，形成一个 `hPort.toHost.hValid`。
- 对所有 fromHost channel 的 `ready` 做 AND，形成一个 `hPort.fromHost.hReady`。
- 通过 `DecoupledHelper` 一次性推进整组 toHost 或 fromHost channel。

这正好违背 NIC leaf channel 的实际结构：`nic.out.*`、`nic.in.*`、`macAddr`、`rlimit`、`pauser` 不是一个应该被单个 bidirectional token 锁死的接口集合。

## 本轮代码状态

当前已完成的静态修复方向是把 NIC bridge 改成 channelized leaf channels：

- `NICBridge` 从 `Bridge[HostPortIO[NICBridgeTargetIO]]` 改为 `Bridge[NICBridgeHostIO]`。
- target stub 和 host implementation 都使用 `ChannelizedHostPortIO`。
- `nic.out.valid/data/keep/last` 是独立 `InputChannel`。
- `nic.in.valid/data/keep/last`、`macAddr`、`rlimit.*`、`pauser.*` 是独立 `OutputChannel`。
- SimpleNIC 本地继续保留 leaf-level ready/valid/fire mask、blocker count、PCIE bigtoken、queue token 等可综合 debug regs。

生成 SV 已确认：

- `SimpleNICBridgeModule` 端口已变为 `hPort_nicOut*`、`hPort_nicIn*`、`hPort_macAddr`、`hPort_rlimit*`、`hPort_pauser*`。
- 不再存在 `SimpleNICBridgeModule_0_hPort_toHost/fromHost/hBits` 聚合端口。
- `FireSim-generated.const.h` 已包含新的 `chan_to_host_*` / `chan_from_host_*` debug register offset。

这与 FireSim 文档要求一致，也解释了为什么 no-NIC 的 UART/TSI 路径原本能工作，而带 NIC 的 hardware 会进入当前问题。
