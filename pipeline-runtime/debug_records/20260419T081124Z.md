## 新观察

### 1. 当前最合适的 marker 验证候选就是 `hello`

原因：

- 现成最小 TraceV metasim 链路已经跑通过。
- 单核、程序极短，不会再出现 `segment3` 那种长 prefill 隐藏 marker 的问题。
- 只要把 `selector=0` 改成 `selector=3`，再埋入两条 marker，
  就能干净验证：
  - exact instruction trigger 是否生效
  - marker 命中后 host 是否发生 nonzero pull
  - `TRACEFILE-C0` 是否非零

### 2. 新增了 `hello-marker.c`

程序结构：

1. 读 `marchid`
2. 执行 start marker：`.word 0x00008013`
3. 打印 `Hello world from core 0, a ...`
4. 执行 end marker：`.word 0x00010013`

这让 trace 窗口尽量短且语义清晰。

### 3. 新增了本地 metasim `selector=3` runtime config

新增配置：

- `selector: 3`
- `start: "ffffffff00008013"`
- `end: "ffffffff00010013"`

其余参数尽量复用已跑通的最小 `hello` 链路，减少变量。

### 4. 本地编译与 marker 验真已通过

编译结果：

- `tests/hello-marker.riscv` 成功生成

反汇编确认：

- `main` 位于 `0x80000230`
- start marker 位于 `0x80000264`
- end marker 位于 `0x80000274`

并且对应指令字准确为：

- `0x00008013`
- `0x00010013`

## 分析

- 这条新路径不是为了解决 `segment3` 功能本身，
  而是为了把问题拆开：
  先验证 **marker / selector=3 / TRACEFILE** 这条精确触发链路本身；
  再回到更重的 `segment3`。
- 如果 `hello-marker` 能在本地 metasim 下稳定打出非零 `TRACEFILE-C0`，
  就能大幅降低对当前 `segment3` 失败原因的歧义。
