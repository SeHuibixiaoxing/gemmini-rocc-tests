## 已钉住的问题

F2 host 侧 CPU-managed stream read 使用 `fpga_pci_peek64()`，软件语义是每次从 BAR4 读一个 64-bit stream beat：

```text
sims/firesim/sim/midas/src/main/cc/simif_f2.cc
```

但 F2 shell 的 PCIS AXI port 是 512-bit，HDK 文档和 BFM 都显示 shell 侧只支持/上报 `AWSIZE/ARSIZE=6`。旧版 `firesim_pcis_width_bridge_512_to_64.read_lane_mask()` 在 `arsize=6` 时返回 `8'hff`，导致一次 host `peek64` 会向下游 `CPUManagedStreamEngine` 发起 8 次 64-bit read。

`CPUManagedStreamEngine` 的 to-host stream read 是 destructive FIFO dequeue。因此旧逻辑会让 host 每读回 8 字节，硬件实际消费 64 字节，丢掉另外 7 个 64-bit beat。这会破坏 NIC token/bigtoken 边界，是当前 NIC 双向通信无法稳定形成闭环的高置信主因。

## 本轮修复

修改：

```text
sims/firesim/platforms/f2/aws-fpga-firesim-f2/hdk/cl/developer_designs/cl_firesim/design/cl_firesim.sv
```

将 `read_lane_mask()` 改为无论 shell 报什么 `ARSIZE`，都只选择 `addr[5:3]` 指定的一个 64-bit lane：

```systemverilog
read_lane_mask = 8'b0000_0001 << lane;
```

这样每个 host `fpga_pci_peek64()` 只会消费一个 downstream 64-bit CPUManaged stream beat，返回数据仍放在 shell 512-bit `rdata` 中由地址指定的 lane，匹配 CPU 对 BAR4 offset 的 64-bit load 语义。
