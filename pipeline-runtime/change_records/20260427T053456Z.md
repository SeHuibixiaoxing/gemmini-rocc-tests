## 修改内容

- 新增 `PIPELINE_RUNTIME_DMA_FORCE_DIRECT_ENABLE`，启用后 `dma_chunk_needs_bounce()` 恒返回 false。
- 将 fixed profile 升到 `pairdummy-sbus128-fixed-v25`，默认 `PIPELINE_RUNTIME_DMA_FORCE_DIRECT_ENABLE=1` 且 `PIPELINE_RUNTIME_DMA_BOUNCE_BYPASS_ENABLE=0`。
- 把 direct-only / local-GDB 变量接入 host-init、guest env render、FireMarshal env 转发、workflow show/debug-preflight 和 local/remote freshness 输出。
- 新增 `pairdummy-local-gdb` workload、guest runner、cfg32_nic runtime config 和 workflow wrapper。
- local-GDB runner 默认断在 `main`，继续运行到 timeout 或退出后收集 `bt`、registers 和 `$pc` 指令窗口。
- local freshness 现在直接解析 workload JSON 的 `run` 字段并校验镜像 `/firemarshal.sh`，remote freshness 也打印 `DMA_BOUNCE_BYPASS` 状态。

## 原因

当前目标 bitstream 已包含 DMA 不对齐搬运优化；本轮软件侧不应继续因为 host/src 与 dst mod64 不一致进入 bounce buffer。`DMA_BOUNCE_BYPASS` 会跳过真实搬运，不适合作为 direct 路线。
