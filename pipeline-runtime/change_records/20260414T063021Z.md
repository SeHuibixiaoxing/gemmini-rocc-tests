## 本轮目标

- 把 `set_src` 前的默认 probe 从高扰动 monitor 指令改成低扰动 ReRoCC/manager 快照。
- 让下一轮 rerun 更快地区分：
  - cfg/opcode 绑定异常
  - manager 前端 busy
  - rocc/DMA busy

## 修改原因

- 当前稳定 blocker 已经收敛到 `set_src` 边界，
  继续在该点前插入多条 `read_monitor` 指令会额外施压 ReRoCC credit / ack 路径，
  容易改变绝对 stall token。
- 现阶段更需要的是：
  在尽量不改硬件时序的前提下，
  看到 `cfg/opcode` 绑定和 `manager/rocc busy` 状态。

## 代码修改

- `src/prt_dma.c`
  在 fixed-load `set_src` 之前新增：
  `phase=program-pre-src-rr`
  快照日志，包含：
  - `opc_binding`
  - `cfg_state`
  - `mgr_busy`
  - `rocc_busy`
- 其中：
  - `cfg/opcode` 来自现有 RR CSR 读取
  - `mgr_busy/rocc_busy` 来自 ReRoCC manager control 寄存器，
    通过 guest `/dev/mem` 读取
- 旧的 `program-pre-src-monitor` 逻辑保留，
  但新增环境开关：
  `PIPELINE_RUNTIME_DMA_FIXED_LOAD_MONITOR_PROBE_ENABLE`

- `scripts/pairdummy_sbus128_fixed_env.sh`
  将
  `PIPELINE_RUNTIME_DMA_FIXED_LOAD_MONITOR_PROBE_ENABLE`
  固定为 `0`，
  使默认 fixed profile 不再注入 monitor 指令。

- `scripts/pairdummy_sbus128_workflow.sh`
  与 freshness 脚本同步展示 / 校验新的 monitor-probe 环境变量。

## 语义影响

- 本轮不改变 DMA/Gemmini/RR 的功能语义。
- 修改只影响 debug 观测方式：
  - 默认 probe 从 monitor 指令切换到 CSR/MMIO 快照
  - monitor 指令改为显式 opt-in

## 风险 / 后续

- `/dev/mem` 读 manager control 依赖 guest 对低地址 MMIO 的访问权限；
  若 guest 限制访问，
  日志会通过 `mgr_busy_rc/rocc_busy_rc` 暴露失败码。
- 这轮仍未直接观测 client credit 计数；
  若新的 `program-pre-src-rr` 仍不足以区分根因，
  下一轮需要更窄地补 client/ack 侧观测。
