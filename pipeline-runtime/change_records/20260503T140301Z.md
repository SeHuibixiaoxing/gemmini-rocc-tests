## 修改内容

本轮不改 `SimpleNICBridgeModule` 的 NIC 数据通路和 ready/valid 语义，只收敛
上一轮新增的高扇出观测面：

- 删除 `NICtokenToBigTokenAdapter` 中 8 个 64-bit `last_pcie_out_words`
  payload snapshot 及对应 OCL attach；
- 删除 to-host 8-entry payload history ring：
  `to_host_hist_data*` / `to_host_hist_meta*`；
- 保留低位宽、低扰动的控制/计数观测：
  ready/valid mask、`first_blocked_*`、`last_blocked_*`、
  `target_cycle_ready`、queue count、adapter fire/backpressure counters；
- 保留 `to_host_packet_seq` 和 `to_host_packet_flit_idx`，用于判断 TX 是否仍
  推进到包边界，但不再把整条 payload 历史接到 OCL；
- 新增 `minobs_build_marker=0x05030001` 只读寄存器，后续生成 Verilog 和
  driver 日志必须能看到该字段，作为“当前 bitstream 确实包含本轮改动”的
  freshness gate。

驱动侧同步删除已撤掉的 MMIO 字段和日志读取，避免 host driver 与 RTL 的 OCL
寄存器表漂移。

## 修改原因

最新 single-core NIC bitstream `agfi-018e48135d1d0b7ce`
（AFI `afi-01fc85fcaa9b6a469`）在 F2 上进入 driver 后立即报：

```text
Attached to BAR4 (PCIS, non-WC)
FireSim fingerprint: 0x46697265
Simulator deadlock detected at target cycle 0
```

静态对比显示：05-02 能 boot 的 AGFI 和 05-03 最新失败 AGFI 在 `FPGATop` 形状
以及 grouped sideband ready 关键表达式上基本一致；差异主要集中在
`SimpleNICBridgeModule` 的 debug/CR payload snapshot 规模。由于上一轮已经证明
05-02 booting AGFI 也存在 post-route timing violation，不能把 cycle0 失败直接
钉死为 TIMING 策略问题。本轮先把可疑的大扇出 payload-history OCL taps 收回，
保留 cycle0 现场复原所需的控制链路观测。
