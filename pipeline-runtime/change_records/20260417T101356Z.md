## Change Summary

对专用 debug workload

- `rerocc-lc-linux-coupleddma-bertmini-pipeline-runtime-batch8-fileonly-sync-pairdummy-tracerv-inst.json`

做最小验证性修改：

- 原来：
  - `/usr/bin/firesim-start-trigger && runtime-wrapper && /usr/bin/firesim-end-trigger`
- 现在：
  - `/usr/bin/taskset -c 0 /usr/bin/firesim-start-trigger && /usr/bin/taskset -c 0 runtime-wrapper && /usr/bin/taskset -c 0 /usr/bin/firesim-end-trigger`

## Why

静态排查结果表明：

- TracerV instruction trigger 是每核独立的
- `firesim-start-trigger` 只会 arm 执行它的那个 hart
- runtime 热路径 worker 会在进入 `stage_worker_main()` 后执行 `sched_setaffinity`

因此当前最可疑的问题是：

- shell 执行 trigger 的 hart
- 与 runtime 真正跑 stage0 热路径的 hart

没有对齐。

把这条专用 debug workload 固定到 CPU0，是当前成本最低、语义最局部的验证办法。
