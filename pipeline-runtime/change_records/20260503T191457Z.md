# 为 target-to-host payload corruption 增加真实数据通路寄存边界

日期：2026-05-03T19:14:57Z

## 修改文件

```text
generators/firechip/goldengateimplementations/src/main/scala/SimpleNICBridge.scala
generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.h
generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.cc
```

## 修改内容

在 `NICTokenToBigTokenAdapter` 输出端新增 2-entry 512-bit 队列：

```text
val pcieOutQ = Module(new Queue(UInt(512.W), 2))
pcieOutQ.io.enq.valid := io.ntht.valid && flushThisToken
pcieOutQ.io.enq.bits := outUInt
io.ntht.ready := !flushThisToken || pcieOutQ.io.enq.ready
io.pcie_out <> pcieOutQ.io.deq
```

这个改动把 target->host token packer 和 CPU-managed stream `pcie_out` 之间的宽数据
路径变成明确的时序/弹性边界，避免继续依赖旧 payload-history OCL taps 对综合布局的
偶然扰动。

同时新增两项低宽度可综合观测：

```text
nicbig_pcie_out_enq_count
nicbig_output_queue_count
```

并把最小观测版硬件 marker 更新为：

```text
minObsBuildMarker = 0x05030002
```

host driver 的 SimpleNIC debug dump 已同步读取/打印新寄存器，便于下一轮如果仍失败
时判断：

- target->host token 是否已经进入 `pcieOutQ`；
- `pcieOutQ` 是否被下游 CPU-managed stream 背压；
- `NICtokenToBig` 自身的 fire 计数与 queue enq 计数是否一致。
