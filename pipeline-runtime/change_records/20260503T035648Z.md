## 原因

04-30 通过版的 generated RTL 没有 `configChannelReady` / `fromHostAllReady` 聚合；
`hport_from_host_valid/ready` 读数和 `targetCycleReady` 只反映 `hPort.nicIn`。

上一轮留下的聚合逻辑不改变 NIC 数据提交路径，但它给 `macAddr/rlimit/pauser.ready`
增加了额外 debug fanout。由于当前回归已经证明 payload snapshot / debug surface 这类
综合形态会影响 F2 上的结果，本轮把这类未被旧通过版验证的观测差异也回退。
