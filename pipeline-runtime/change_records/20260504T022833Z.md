## Change

The target-to-host CPU-managed stream path now gates the outgoing FIFO dequeue
and the wide-to-narrow adapter input valid with an active AXI read request:

```scala
val readRequestActive = grant && axi4.ar.valid
ser_des.io.wide.in.valid  := outgoingQueueIO.deq.valid && readRequestActive
outgoingQueueIO.deq.ready := ser_des.io.wide.in.ready && readRequestActive
```

This prevents the width adapter from prefetching a 512-bit token out of the
FIFO before the host stream driver has observed a nonzero FIFO count and issued
the corresponding AXI read.

The next single-core NIC runtime also enables low-volume software-side
observability:

```text
+simplenic-token-debug=32
+cpu-managed-stream-debug=1
```

These plusargs do not change hardware. They make the next failure scene show
CPU-managed stream count polling and the first target-to-switch token snapshots.

## Why

The previous latch fix made the 512-bit-to-64-bit readout stable, but it also
allowed the latch to hide one token from the FIFO count MMIO. The host stream
driver polls that count before reading, so hiding the only token can deadlock
the stream before Linux boot.
