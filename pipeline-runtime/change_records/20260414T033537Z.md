## 本轮目标

- 修正静态审计里已经确认的 runtime 语义偏差。
- 让 `vAccIdxList` 真正参与 stage 内 manager 槽位绑定。
- 保持 `DRAM_DEPEN` 与对齐文档中的 HybridMapper/MudnacSim 语义一致。

## 修改文件

- `src/prt_schedule_action.c`
- `src/prt_runtime.c`
- `src/prt_yaml_loader.c`
- `change_records/20260414T033537Z.md`

## 修改原因

- `vAccIdxList` 之前只做合法性校验，没有真实影响 `stage_mgr_ids` 的槽位顺序，runtime 会默认按 rr 分配顺序写回 manager。
- `DRAM_DEPEN` 在存在 ring 时会把 `dram_base_addr` 清零，错误退化成纯 ring/SPM 语义。
- YAML loader 对 `vAccIdxList` 只做范围检查，没有保证它是完整无重复的 slot permutation。

## 语义影响

- `vAccIdxList[k]` 现在决定第 `k` 个 artifact manager 绑定最终写入 stage 的哪个 virtual slot。
- 若 artifact 给出重复或缺失的 `vAccIdxList`，runtime 会在 pipeline YAML 校验阶段直接拒绝。
- `DRAM_DEPEN` 在 entry/export 侧即使绑定了 ring，也继续保留 model alias 解析出的 DRAM dependency base。
