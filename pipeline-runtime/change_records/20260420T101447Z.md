## 修改内容

- `include/prt_breadcrumb.h`
  - 新增 5 个 Gemmini pointwise precall 相位：
    - `...PRECALL_AFTER_SCOPE_MARKER`
    - `...PRECALL_AFTER_BINDING_SNAPSHOT`
    - `...PRECALL_DISPATCH_DECIDED`
    - `...PRECALL_AFTER_POSTFLUSH_SNAPSHOT`
    - `...PRECALL_READY`
- `scripts/decode_prt_breadcrumb.py`
  - 新增上述 phase 名称与 Gemmini decode 集合映射
- `src/prt_gemmini_adapter.c`
  - 新增 budgeted compact snapshot helper：
    `prt_log_pointwise_precall_snapshot_compact()`
  - 在
    `conv_call_for_manager_sync_strided()`
    的 pointwise precall 路径中，
    依次补齐 5 个新 breadcrumb
  - 复用一次性计算得到的
    `pointwise_fallback_type`
    贯穿 precall / call-begin，
    避免在同一窗口反复重算

## 语义影响

- 不改变 Gemmini / DMA / ReRoCC 指令顺序
- 不改变 fence / flush / release 语义
- 不改变 pointwise dispatch 选择
- 新增 compact snapshot 只在
  `prt_log_gate_allow_deep_logs_budgeted()`
  允许时输出，
  默认不会常开

## 预期收益

- 把当前
  `rr_acquire_after_call -> pointwise_call_begin`
  的大窗口，
  拆成 5 个更窄的 caller-side 子阶段
- 让下一轮 live run 能区分：
  - scope marker
  - RR binding snapshot
  - dispatch 判定
  - post-flush cached xlate snapshot
  - call-begin 之前的最后 ready 边界

## 风险

- 新增 Gemmini breadcrumb phase 后，
  旧 decoder 若未同步更新会把 phase 打成数字；
  本轮已同步脚本
- compact snapshot 虽然预算受控，
  仍应只在目标 stage/subbatch 的窄窗口里启用
