# Change Record 2026-05-04 06:09 UTC

Category: gdbserver

## Goal

Fix the single-core NIC bridge boot-before-Linux deadlock seen on
`agfi-05336229a1326f9ff`, while preserving the already-required CPU-managed
stream read gating fix.

## Related Debug Record

- `../debug_records/20260504T060924Z.md`

## Changed Files

- `generators/firechip/goldengateimplementations/src/main/scala/SimpleNICBridge.scala`
- `sims/firesim/sim/midas/src/main/scala/midas/core/CPUManagedStreamEngine.scala`

## Change

`SimpleNICBridge.scala` now treats the from-host NIC token handshake as the
actual `nicIn` channel handshake:

```scala
val nicInChannelReady = hPort.nicIn.ready
val fromHostChannelReady = nicInChannelReady
val nicInChannelValid = hPort.nicIn.valid
val fromHostChannelValid = nicInChannelValid
val targetBlockedFromHostChannels = fromHostTokenAvailable && !hPort.nicIn.ready
```

This removes the bad dependency on unrelated configuration channels when
deciding whether a NIC target cycle can advance.

`CPUManagedStreamEngine.scala` keeps the earlier read-request gate:

```scala
val readRequestActive = grant && axi4.ar.valid
ser_des.io.wide.in.valid := outgoingQueueIO.deq.valid && readRequestActive
outgoingQueueIO.deq.ready := ser_des.io.wide.in.ready && readRequestActive
```

This prevents the to-host width adapter from prefetching a 512-bit token out of
the FIFO before the host driver has observed a nonzero FIFO count and issued an
AXI read.

## Why

The live host GDB dump showed `debug_cycle = 0` and `target_cycle_ready = 0`.
That proves the guest never reached boot; the bridge could not complete the
first target token cycle. The source-level readiness aggregation was too broad:
it included config channels that are not part of the steady NIC packet token
exchange.

## Risk / Follow-Up

- The fix is intentionally narrow: only NIC target-cycle gating and the
  CPU-managed to-host stream dequeue semantics are touched.
- The next bitstream must be checked after launch to ensure generated Verilog
  includes both fixes before waiting for AFI creation.
- If the new AGFI reaches Linux, resume software-breakpoint-only `gdbserver`
  regression. Hardware breakpoints/watchpoints remain out of scope for this
  round.
