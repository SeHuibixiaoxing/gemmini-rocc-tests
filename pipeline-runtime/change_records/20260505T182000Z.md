## 结论

- pipe/ring 软件等待有 timed wait/retry。
- ReRoCC acquire 有 retry 上限。
- 但 `hw_dma_fence()`、`rr_fence()` 和 `gemmini_fence()` 没有软件 timeout 包裹。
- 因此外层 watchdog 可以设置 `stop_requested`，但如果 worker 已停在硬件等待内，主线程仍可能卡在
  `pthread_join()`。

## 对后续测试的影响

新 `cfg32_nic` AGFI 跑起来后，首轮 remote GDB 不应先深单步业务逻辑，而应先做线程/PC 分流：

- `info threads`
- `thread apply all bt`
- `thread apply all p/x $pc`
- `thread apply all x/6i $pc`

重点判断 PC 是在 pipe/ring wait、`pthread_join`、`hw_dma_fence`、`prt_rr_fence_scope` 还是
`gemmini_fence`。这会直接决定下一轮查软件调度、DMA/TL/SPM xlate、还是 Gemmini/ReRoCC manager
ownership。
