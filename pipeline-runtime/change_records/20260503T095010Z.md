# 修复 single-core NIC from-host sideband ready 回归

日期：2026-05-03T09:50:10Z

## 修改文件

```text
generators/firechip/goldengateimplementations/src/main/scala/SimpleNICBridge.scala
```

## 修改内容

恢复 `SimpleNICBridgeModule` 中 from-host channel 的 grouped ready/valid：

- `macAddr.ready`、`rlimit.ready`、`pauser.ready` 重新组成
  `configChannelReady`；
- `fromHostChannelReady` 重新要求 `nicIn.ready && configChannelReady`；
- `configChannelValid` 重新覆盖 `macAddr.valid`、`rlimit.valid`、`pauser.valid`；
- `fromHostChannelValid` 重新要求 `nicIn.valid && configChannelValid`；
- `targetCycleReady`、`targetBlockedFromHostChannels`、`fromHostEmptyBlocked`
  和相关 debug blocker 使用 grouped `fromHostChannelReady`。

## 修复原因

05-03 失败 bitstream `agfi-0a8a558628a493d31` 在 Linux boot 前报
`Simulator deadlock detected at target cycle 0`。

静态对比 05-02 通过版 generated RTL 后，确认 05-03 失败版把
`macAddr/rlimit/pauser` 这些 NIC from-host sideband output channels 从
target-cycle close 条件里漏掉了，只剩 `nicIn.ready`。这和 targetcycle debug
现场里的 sideband backpressure 现象一致。

本轮修改不是恢复旧的 valid/ready 互等写法。`fromHostValidDrive` 仍为
`true.B`，sideband valid 继续稳定驱动；本轮只恢复 ready 汇聚和 blocker 观测。
