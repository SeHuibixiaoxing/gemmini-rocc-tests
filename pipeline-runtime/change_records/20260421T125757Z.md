## 修改内容

### 1. 为 bounce path 增加运行时开关

在 `prt_dma.c` 中新增 `PIPELINE_RUNTIME_DMA_BOUNCE_BYPASS_ENABLE`：

- fixed-load bounce path 命中时：
  - 跳过 `memcpy(src -> bounce)`
  - 跳过 `virt_to_phys(bounce_ptr)`
  - 跳过真实 DMA submit/wait
  - 仅推进 `copied/remaining`
- export bounce path 命中时：
  - 跳过 `virt_to_phys(bounce_ptr)`
  - 跳过真实 DMA submit/wait
  - 跳过 `memcpy(bounce -> dst_host)`
  - 仅推进 `copied/remaining`

同时保留了两类 coarse 日志：

- `phase=bounce-bypass`
- `phase=first-chunk-bounce-bypass`

用途不是长期保留业务逻辑，而是作为一次性根因排除实验。

### 2. 把实验开关打通到 guest 镜像

为了确保 rerun 真正使用了该实验开关，补了完整 env 传播链：

- `host-init.sh`
- `render_pairdummy_guest_env.sh`
- `pairdummy_sbus128_fixed_env.sh`
- `verify_pairdummy_firemarshal_image_freshness.sh`

从而能做到：

- manager shell 里设置
  `PIPELINE_RUNTIME_DMA_BOUNCE_BYPASS_ENABLE=1`
- 经过 image-closure 写入 `/firemarshal.env`
- 在 rerun 前由 `image-freshness` 输出直接验证该 env 已入镜像

## 结论

- 这组改动成功把 “只在 bounce path 命中时旁路真实 DMA/搬运” 这个实验能力接入了主线 workflow；
- 但实际 rerun 结果表明，当前主线 plateau 并没有命中该路径；
- 因而这组代码改动的价值主要是：
  - **把 `bounce path` 从当前最优先怀疑对象中基本排除**
  - 把后续调试焦点重新收敛到 direct export 主线
