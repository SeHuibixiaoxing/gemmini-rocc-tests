## 具体修改

### 1. 新增 guest-side `ptrace` probe helper

新增：

- `rerocc_ptrace_peek.c`

功能：

- `ptrace(PTRACE_ATTACH)` 到目标 pid
- 通过 `PTRACE_GETREGSET(NT_PRSTATUS)` 读取 RISC-V `pc/ra/sp/s0/a0/a1`
- 读取 `pc` 周围一小段指令窗口
- 以纯文本形式输出

目标不是做持续 profile，
而是在 freeze rerun 中只做一两次 one-shot attach，
拿到“卡在什么 PC”这种直接证据。

### 2. 让 Linux build 产出 helper binary

在 `rerocc-linux-tests/Makefile` 中把：

- `rerocc_ptrace_peek-linux`

加入 `LINUX_EXTRA_BINS`，
确保它和现有 linux test binaries 一起被交叉编译。

### 3. 升级 runner 的 guest-side proc probe

在 `run_rerocc_pipeline_runtime_bertmini.sh` 中新增：

- detail gate:
  - `PIPELINE_RUNTIME_RUNNER_PROC_DETAIL_ENABLE`
  - `PIPELINE_RUNTIME_RUNNER_PROC_DETAIL_LABEL_REGEX`
- delayed one-shot probe:
  - `PIPELINE_RUNTIME_RUNNER_BIN_DELAY_PROBE_ENABLE`
  - `PIPELINE_RUNTIME_RUNNER_BIN_DELAY_PROBE_DELAYS`
- ptrace gate:
  - `PIPELINE_RUNTIME_RUNNER_PTRACE_PROBE_ENABLE`
  - `PIPELINE_RUNTIME_RUNNER_PTRACE_PROBE_TOOL`
  - `PIPELINE_RUNTIME_RUNNER_PTRACE_PROBE_DETAIL_BYTES`

并把 `append_proc_stage()` 扩展为在 detail 模式下追加：

- `/proc/<pid>/syscall`
- `/proc/<pid>/stack`
- `/proc/<pid>/sched`

同时在 runtime child 启动后：

- 立即写一次普通 proc snapshot
- 立即尝试一次 ptrace snapshot
- 再按延迟列表触发 one-shot probe

这样即使 TracerV 仍为 0，
capture 里也会留下：

- 它是否卡在 syscall / kernel wait
- 或者它停在哪个 user PC

### 4. 让 `workerpc` workflow 默认启用低频 delayed probe

在 `pairdummy_sbus128_tracerv_workerpc_workflow.sh` 中新增默认导出：

- `PIPELINE_RUNTIME_RUNNER_BIN_PROC_POLL_SECONDS=60`
- `PIPELINE_RUNTIME_RUNNER_PROC_DETAIL_ENABLE=1`
- `PIPELINE_RUNTIME_RUNNER_PROC_DETAIL_LABEL_REGEX=after-bin-spawn|bin-delay-probe|after-bin-wait`
- `PIPELINE_RUNTIME_RUNNER_BIN_DELAY_PROBE_ENABLE=1`
- `PIPELINE_RUNTIME_RUNNER_BIN_DELAY_PROBE_DELAYS=180,480,900`
- `PIPELINE_RUNTIME_RUNNER_PTRACE_PROBE_ENABLE=1`
- `PIPELINE_RUNTIME_RUNNER_PTRACE_PROBE_TOOL=/root/rerocc-linux-tests/rerocc_ptrace_peek-linux`
- `PIPELINE_RUNTIME_RUNNER_PTRACE_PROBE_DETAIL_BYTES=32`

理由：

- 频率降低，避免持续写 guest 文件
- 但在 long-running freeze rerun 中，
  仍能在几个关键时间点留下直接快照

### 5. 让 effective guest env 渲染链支持这些新变量

在 `render_pairdummy_guest_env.sh` 中把上述 runner/probe 变量加入
`runner_env_names`，
确保 workflow 导出的覆盖值能真正写入 `/firemarshal.env`。

### 6. 修正 coupleddma workload 的 overlay staging

当前实际构建使用的是：

- `rerocc-linux-tests-coupleddma/workload/host-init.sh`

它原先只复制：

- `rerocc_pipeline_runtime-linux`

到 pipeline-runtime overlay，
不会把新 helper binary 带进 image。

因此补了三处：

- `check_built_linux_binaries()` 现在要求
  `rerocc_ptrace_peek-linux`
- `rebuild_pipeline_runtime_binary()` 同时构建
  `rerocc_pipeline_runtime-linux rerocc_ptrace_peek-linux`
- `stage_pipeline_runtime_overlay()` 复制并 `chmod +x`
  `rerocc_ptrace_peek-linux`

这一步是本轮 image freshness 从 fail 变成 pass 的关键修正。

### 7. 把 helper 纳入 image freshness 闭环

在 `verify_pairdummy_firemarshal_image_freshness.sh` 中新增：

- local source:
  `build/rerocc-linux-tests/rerocc_ptrace_peek-linux`
- guest path:
  `/root/rerocc-linux-tests/rerocc_ptrace_peek-linux`

从而保证后续 rerun 前，
能直接发现 image 里 helper 缺失的问题。
