## 本轮修改

### 1. 补齐 `stage_prepare_exec_views()` 内 `spm-xlate` flush 的 breadcrumb context

- 文件：
  - `src/prt_runtime.c`
- 修改：
  - 在 `stage_prepare_exec_views()` 内部、
    `runtime_flush_stage_spm_xlate(rt, stage_id)` 调用前，
    显式设置：
    - `segment_idx`
    - `global_stage_id`
    - `local_stage_id`
    - `subbatch=ANY`
  - flush 返回后立刻清除 context。
- 目的：
  - 让准备阶段的 `spm-xlate` breadcrumb 不再被当前 fixed profile 的
    `segment/global_stage/local_stage` 过滤静默丢弃。
- 预期效果：
  - 下一轮 FPGA rerun 中，
    `spm_xlate_release_fence_end / release_begin / release_end / restore_*`
    可以直接出现在 breadcrumb binary 里，
    不必再只靠 sparse 文本尾部猜 frontier。

### 2. 补齐 breadcrumb 解码脚本对 `phase=309` 的支持

- 文件：
  - `scripts/decode_prt_breadcrumb.py`
- 修改：
  - 新增 `309 -> rr_release_after_csr_write`
- 目的：
  - 让 `prt_rr_release_scope()` 当前已经落地的
    `RR_RELEASE_AFTER_CSR_WRITE` phase
    在 host 侧 decode 时不再显示成匿名 `phase_309`。

### 3. 让 `triage_prt_capture.py` 直接支持 watchdog capture prefix

- 文件：
  - `scripts/triage_prt_capture.py`
- 修改：
  - 允许把
    `tmp/.../host-watchdog-<ts>` 这种 prefix
    直接作为位置参数传入；
    脚本会自动解析：
    - `.guest-breadcrumb.bin`
    - `.guest-sparse-log.txt`
    - `.guest-trigger-log.txt`
- 目的：
  - 和当前 host-watchdog 的实际产物形态对齐，
    避免每次手工改成目录或显式逐文件传参。
