## 修改原因

- 现有 `bertmini` 主线 artifact 面向 `12` 个 Gemmini manager；为了隔离当前 cfg / manager 预算问题，需要一版明确受限到 `6` 个 Gemmini/DMA 槽位的新 mapping。
- 现有 workflow 直接把 `workload json` 和 fixed env 写死在 `12-core` 主线上，不足以安全复用到 `g6` 变体。
- 单纯依赖 shell 中的 `PAIRDUMMY_FIXED_ENV_SCRIPT` 传递给 FireMarshal host-init 不可靠；第一次本地 `image-closure` 证明最终 guest `/firemarshal.env` 仍回落到 `12-core` baseline。

## 语义影响

- 新增一个 runtime hardware target：
  `rerocc_globalnoc_pairmanager_dummy16x16_c4_g6_d6_spad1024kb_dram19_noc64_mac256_sbus128`
  - 仍复用当前 `12-pair sbus128` bitstream 对应的 `chipyard_config`
  - 但 artifact 合同与 runtime manager 预算收敛到 `6 Gemmini + 6 DMA`
- 新增 `pairdummy_sbus128_g6_fixed_env.sh`：
  - `PROFILE_ID=pairdummy-sbus128-g6-fixed-v1`
  - `TARGET_KEY=...g6_d6...`
  - `NUM_GEMMINI=6`
  - `NUM_DMA=6`
- `pairdummy_sbus128_workflow.sh` 现在允许通过 `PAIRDUMMY_WORKLOAD_JSON` 选择不同 workload json；默认主线行为不变。
- 新增 `pairdummy_sbus128_g6_workflow.sh`：
  - 固定绑定 `g6` env + `g6` workload json
  - 不改现有 `12-core` workflow 的默认入口
- 新增显式 `g6` host-init / workload json：
  - 避免 FireMarshal 构建阶段再依赖 shell-only override
  - 让 host-init 在 build/install 时稳定写出 `g6` 版本的 `overlay/firemarshal.env`
