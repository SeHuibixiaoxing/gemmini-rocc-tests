## 修改内容

- 在 runner 脚本中新增 `PIPELINE_RUNTIME_RUNNER_BIN_DELAY_PROBE_FORCE_SYNC`。
- 仅在 `bin-delay-probe-*` 后台一次性 probe 命中时，如果该开关为 `1`，执行单次 `sync`。
- 在 `workerpc` workflow 中默认导出：
  `PIPELINE_RUNTIME_RUNNER_BIN_DELAY_PROBE_FORCE_SYNC=1`。

## 原因

- 当前 live run 里：
  - `runner-proc.stage` 大小增长到 `13721`
  - 但 `mtime` 仍停在 guest 启动后第 `4s`
  - `breadcrumb.bin` `mtime` 也只到第 `6s`
- 这说明 delayed probe 的内容即使在 guest 内执行了，也可能长期滞留在 guest page cache，
  host 侧 `debugfs` live 读取看不到。
- 当前问题不是“再加更多热路径日志”，而是把已有低频 stuck-state 快照真正暴露给 host 观测面。

## 风险 / 后续

  频率仍受 `180,480,900s` 这类低频 one-shot 控制，不进入 runtime 热路径。
- 当前 live run 使用的是旧镜像；
  若要验证该修正，需要重新做 image closure / freshness / infrasetup / runworkload。
