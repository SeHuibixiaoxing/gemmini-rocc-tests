# Change Record 20260429T221723Z

调试类别：gdbserver

## 修改目标

修复 F2 host driver 对 CPU-managed stream BAR4 的错误访问模式。当前 BAR4 被映射成 write-combining，但 CPU-managed stream 是 FIFO/破坏性读写语义，不能按普通 WC 内存访问。

## 修改内容

文件：

```text
sims/firesim/sim/midas/src/main/cc/simif_f2.cc
```

改动：

- `fpga_pci_attach(... APP_PF_BAR4, BURST_CAPABLE, ...)` 改为 `fpga_pci_attach(... APP_PF_BAR4, 0, ...)`；
- 启动日志从 `Attached to BAR4 (PCIS)` 改为 `Attached to BAR4 (PCIS, non-WC)`；
- 增加注释说明 BAR4 这里承载 CPU-managed stream FIFO，不能使用 write-combining。

## 影响范围

这是 host driver 软件修改，不改变 RTL，不需要重新构建 bitstream。下一轮验证需要重新执行 `infrasetup`，确保 run host 上的 `FireSim-f2` driver 重新编译并部署。

## 验证计划

使用最新 NIC AGFI `agfi-019e0b22099a5214b` 重新跑 fresh F2 runfarm：

- `launchrunfarm`
- `infrasetup`
- `runworkload`

重点验证：

- `FireSim-f2` 启动日志是否显示 `Attached to BAR4 (PCIS, non-WC)`；
- `tap0` 是否能收到 target ARP reply；
- gdbserver TCP 连接是否建立；
- 若失败，是否还出现 F2 shell `dma-pcis-timeout`。
