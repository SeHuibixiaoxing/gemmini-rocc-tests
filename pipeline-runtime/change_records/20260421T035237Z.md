## 修改内容

- 在 `prt_dma.c` 中新增只针对
  `stage=0 / tensor=6 / copied=0 / 可选 page range`
  的 raw marker：
  - `program_begin`
  - `program_post_fence`
  - `program_post_dst`
  - `program_post_src`
  - `wait_before_fence`
  - `wait_after_fence`
  - `wait_before_shared_fence`
  - `wait_after_shared_fence`
  - `batch_release_begin`
  - `batch_release_end`
- 为这些 marker 增加运行时 page 过滤：
  - `PIPELINE_RUNTIME_DMA_TRACERV_PAGE_START`
  - `PIPELINE_RUNTIME_DMA_TRACERV_PAGE_END`
- 在 export host-copy 路径中，把 DMA-window scope 从 direct-path 补到 bounce-path：
  - bounce 分支现在也会 `scope_push/scope_pop`
  - bounce 分支也会登记 `tracerv_release_page_idx/copy_bytes`
  - 这样下一轮不会因为目标页刚好走 bounce 而得到“没触发”的假阴性
- 在 workflow 中加入：
  - `PAIRDUMMY_TRACERV_START_INST`
  - `PAIRDUMMY_TRACERV_END_INST`
  并生成 effective runtime config，避免手改 yaml
- 在 freshness 脚本中加入新 marker 的存在性校验
- 把本轮计划和状态写回文档

## 原因

- 现有 worker 级 marker 只能回答“worker 大致有没有进入/退出”，
  不能回答 submit / wait / shared fence / batch release 到底卡在哪一段
- 目标 export 路径存在 direct-path 与 bounce-path 两套 submit/wait 分支；
  如果只在 direct-path 建立 DMA-window scope，
  则实际运行一旦落到 bounce-path，`TraceV selector=3` 结果就会被错误解释
- 因此这一轮必须先把 trigger 覆盖面修正为“路径无关”，
  否则下一轮 rerun 的二分结论不可靠
