# SimpleNIC host-driver empty round 节流与 gdbserver 链路验证

日期：2026-05-01T02:32:00Z

## 修改

- `generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.cc`
- `generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.h`

新增/使用 host-driver 侧可配置项：

```text
+simplenic-empty-switch-poll-interval=<N>
```

当前 gdbserver smoke runtime 使用：

```text
+simplenic-relaxed-required-bytes=1
+simplenic-empty-switch-poll-interval=1024
+simplenic-token-debug=0
+heartbeat-polling-interval=100000000
```

## 目的

上一轮 `FireSim-f2` host 进程 gdb 采样显示热点落在：

```text
simplenic_t::tick -> clear_bigtoken_headers
```

即 target 没有 NIC payload 时，host driver 仍高频执行空 round 的 shared-memory
交换和 buffer header 清理，严重拖慢 Linux boot，看起来像 target 停在 early boot。

本修改把“target->host 无 payload”的空 round 分成两类：

- 大多数空 round 直接由 FPGA-side bridge 的 no-packet host token 语义覆盖；
- 每隔 `N` 个空 round 才轮询一次 host-side switch，避免完全饿死 tap0/host-to-target 包。

这属于 host-driver 软件修复；不需要重新构建 FPGA bitstream，但需要重新编译并部署
`FireSim-f2` driver。

## 结论

- NIC/Linux/IceNet/gdbserver/TCP/RSP 链路已打通。
- 之前的 SimpleNIC 空轮询 host-driver 热点已被推进过去。
- 当前不需要新的 bitstream 来修 gdbserver 链路。
- 后续使用 `gdbserver --once` 时，第一次连接必须是真实 `gdb target remote`；
  不要用 `nc` / `telnet` / 端口扫描消耗唯一连接。
