## 变更目标

- 基于当前 live `tracerv-inst` 证据，
  为下一轮 rerun 增加一个不依赖 `selector=3` instruction trigger 的
  `worker-PC` TracerV fallback workflow。

## 具体修改

### 1. 让现有 PC-trigger workflow 支持 wrapper 级参数覆盖

在 `pairdummy_sbus128_tracerv_workflow.sh` 中增加以下可覆盖变量：

- `PAIRDUMMY_TRACERV_SCRIPT_NAME_OVERRIDE`
- `PAIRDUMMY_TRACERV_SESSION_PREFIX`
- `PAIRDUMMY_TRACERV_DESCRIPTION`
- `PAIRDUMMY_TRACERV_TRIGGER_USAGE_DESC`
- `PAIRDUMMY_TRACERV_SHOW_NOTE`
- `PAIRDUMMY_TRACERV_SHOW_SELECTOR`
- `PAIRDUMMY_TRACERV_SHOW_START_PC`
- `PAIRDUMMY_TRACERV_SHOW_END_PC`
- `PAIRDUMMY_TRACERV_WORKLOAD_JSON`
- `PAIRDUMMY_TRACERV_RUNTIME_CFG`
- `PAIRDUMMY_TRACERV_HWDB_CFG`
- `PAIRDUMMY_TRACERV_BUILD_RECIPES_CFG`

这样可以复用已有 PC-trigger workflow 主体，
而不必再复制一整份 FireSim manager / tmux / freshness 逻辑。

### 2. 新增 `workerpc` wrapper script

新增：

- `pairdummy_sbus128_tracerv_workerpc_workflow.sh`

该 wrapper 只负责导出上面的 override 变量，然后复用
`pairdummy_sbus128_tracerv_workflow.sh`：

- session prefix:
  `pairdummy-sbus128-tracerv-workerpc`
- workload:
  仍复用 `pairdummy-tracerv-inst` image，
  因为它已经包含 worker marker 指令
- 展示的 PC window:
  `0x2a2b0 -> 0x2ab22`

### 3. 新增 `workerpc` runtime config

新增：

- `config_runtime_..._tracerv_workerpc.yaml`

关键配置：

- `run_farm_tag: pairbertb8d12s128trwpc`
- `tracing.selector: 2`
- `tracing.start: "2a2b0"`
- `tracing.end: "2ab22"`
- `target_config.plusarg_passthrough: "+trace-min-batch=0"`
- workload 继续指向：
  `...pairdummy-tracerv-inst.json`
- suffix tag 独立为：
  `...tracerv-workerpc`

### 4. 把 worker marker PC 校验接到 freshness 链

在 `verify_pairdummy_firemarshal_image_freshness.sh` 中新增了可选校验：

- `PIPELINE_RUNTIME_FIRESIM_TRACERV_WORKER_PC_START_EXPECT`
- `PIPELINE_RUNTIME_FIRESIM_TRACERV_WORKER_PC_END_EXPECT`
- `PIPELINE_RUNTIME_FIRESIM_TRACERV_OBJDUMP`

当这两个期望地址被设置时，
脚本会对 source binary 与 image binary 都做 `objdump`，
要求：

- `0x00008013` 唯一落在期望 start PC
- `0x00010013` 唯一落在期望 end PC

这样后续如果 runtime 改动导致 marker PC 漂移，
`workerpc` workflow 会在 rerun 前直接 fail，
而不会拿着陈旧的 PC 去跑 FPGA。

### 5. 让 `workerpc` wrapper 继承 instruction-marker image 的 freshness 语义

`workerpc` workflow 虽然使用 PC trigger，
但 guest image 仍复用 `pairdummy-tracerv-inst` 变体，
因此 wrapper 默认导出：

- `PIPELINE_RUNTIME_FIRESIM_TRACERV_WORKER_MARKERS=1`

避免 freshness 错把这张 image 判成“unexpectedly present markers”。

## 修改原因

- 当前 live `selector=3` round 中：
  - worker start marker 已确认在真实 freeze 路径之前
  - guest 已再次进入 `stage-fixed-load-sparse slot=1 tensor=1000001`
  - 但 `TRACEFILE-C*` 与 fd `pos` 仍然全为 `0`
- repo 内唯一 instruction-trigger 测例也长期被禁用，
  因而下一步需要一个不依赖 selector `3` 的替代路径。

- source/image binary 都带 worker markers

## 影响范围

- 不改变 guest/runtime 主语义。
- 不移除现有 `tracerv-inst` 路径，只新增一个 `workerpc` fallback。
- 仅影响后续 TracerV 调试 rerun 的控制面选择。
