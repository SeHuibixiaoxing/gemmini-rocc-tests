## 修改内容

### 1. 把 `SimpleNIC` 的两侧 token 统一到同一个 `tFire`

原始实现虽然定义了：

```scala
val tFireHelper = DecoupledHelper(hPort.toHost.hValid,
                                  hPort.fromHost.hReady)
```

但后续并没有真正使用 `tFire` 约束两边同步推进，而是让：

- `ntht_queue.io.enq`
- `htnt_queue.io.deq`
- `hPort.toHost.hReady`
- `hPort.fromHost.hValid`

分别按各自的 queue ready/valid 独立前进。

本轮改成：

- `tFireHelper` 同时纳入
  - `hPort.toHost.hValid`
  - `hPort.fromHost.hReady`
  - `ntht_queue.io.enq.ready`
  - `htnt_queue.io.deq.valid`
- `hPort.toHost.hReady` 由 `tFireHelper.fire(...)` 驱动
- `hPort.fromHost.hValid` 由 `tFireHelper.fire(...)` 驱动
- `ntht_queue.io.enq.valid := tFire`
- `htnt_queue.io.deq.ready := tFire`
- `target.in.valid := ... && tFire`

这样做的目的是：

- 强制每个 fired target cycle 同时完成一份输入 token 和一份输出 token 的交换
- 避免 `SimpleNIC` host bridge 的两条 token 通道在队列层面发生漂移

### 2. 补了简短注释，说明这个改动针对的就是 stream occupancy 漂移

注释直接写明：

- `SimpleNIC` host driver 假设 one input token / one output token per fired cycle
- 如果让两边各自独立排队，会导致 CPU-managed stream occupancy 漂移
- 最终可能表现成 host 侧 `simplenic_t::push()` 返回 0

## 修改原因

本轮 `cfg32 + NIC + gdbserver` 实跑中，

- Linux 没有起来
- `FireSim-f2` 在 `Commencing simulation.` 后立即因为
  `simplenic_t::tick()` 的
  `ERR MISMATCH! on writing tokens in. actually wrote in 0 bytes, wanted 58560 bytes.`
  退出

静态对照后发现：

- `simplenic_t` host 驱动默认一拍一进一出严格对拍
- 但 `SimpleNICBridge.scala` 原实现并没有维持这条语义

因此先做 bridge 级语义修复，再等待下一轮 NIC bitstream 重建验证。
