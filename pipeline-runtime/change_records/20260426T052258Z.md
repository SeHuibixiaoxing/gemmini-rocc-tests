  - 修正 `fromHostFire`：

  - host->target 的 `nic.in/mac/rlimit/pauser` leaf `valid` 改为由 `fromHostValidDrive` 驱动。
  - `htnt_queue.io.deq.ready` 保持由整组 fire 驱动，避免 leaf partial-fire。
  - 补充注释，说明 FAME1 `OutputChannel` 的 `valid` 不能等待 `ready`，否则会形成 ready/valid dependency loop。

## 原因

- `ChannelizedHostPortIO.OutputChannel` 对应 target input channel。
- FAME1 在 target cycle 完成时统一拉高 input channel ready。
- 如果 bridge 的 valid 又等待这些 ready，则 target cycle 无法形成完整 input-valid 集合。
- 当前 FPGA 证据中 `fromHostTokenAvailable=1` 但 `fromHostValidDrive=0`，以及 `wire_input_missing_valid[5] ep_3_nicInValid`，均指向这一问题。
