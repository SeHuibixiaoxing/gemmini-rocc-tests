## 修改内容

- 在 `pairdummy_sbus128_fixed_env.sh` 中新增：
  - `FIRESIM_RUNWORKLOAD_LIVE_IDLE_TIMEOUT_SECONDS=${...:-3600}`
- 保持 `scripts/firesim-prt-host-watchdog.sh` 的全局默认不变：
  - 全局 `idle_timeout_seconds` 仍为 `600`
  - 全局 `live_idle_timeout_seconds` 默认仍为 `10800`
- 在三个 pairdummy workflow 的 `show_config()` 输出中增加：
  - `firesim_live_idle_timeout_seconds=${FIRESIM_RUNWORKLOAD_LIVE_IDLE_TIMEOUT_SECONDS:-}`

## 原因

- 当前这轮 `tracerv-inst` FPGA run 已经出现稳定 plateau：
  - `heartbeat.csv` 持续增长
  - `uartlog` 停在 `S99run` 之后的 `RCU stall`
  - `TRACEFILE-C*` 始终 `0`
  - guest 业务日志、checkpoint、trigger 都不再增长
- 在这种 plateau 下，原来的 `live_idle_timeout=10800` 会让一轮已经收敛的 run 继续空占机约 3 小时
- 但外层 `FIRESIM_RUNWORKLOAD_WATCHDOG_SECONDS` 是绝对总时长 watchdog；
  若一并缩短，可能误伤“仍有真实进展但总时长较长”的 run
- 因此本轮只缩短 pairdummy 主线的 `live_idle_timeout`，
  不改全局默认，也不改外层绝对 watchdog
