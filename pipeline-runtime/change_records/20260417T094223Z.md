## 修改内容
- 将 instruction-trigger workload JSON 的入口从：
  - `run = "firesim-start-trigger && ..."`
  改为：
  - `command = "/usr/bin/firesim-start-trigger && /root/rerocc-linux-tests/run_rerocc_pipeline_runtime_bertmini_fileonly_sync_capture.sh --batch 8 && /usr/bin/firesim-end-trigger"`

## 原因
- FireMarshal 的 `run` 语义是 `script + args`，不是 shell 命令串。
- 原写法会把 `firesim-start-trigger` 当成 workload 目录下的脚本名去解析，直接导致 build 失败。
- `command` 才是 FireMarshal 文档和代码都支持的 shell 片段入口。

## 验证
- 失败日志已明确证明原问题：
  - `ValueError: Run script .../firesim-start-trigger not found.`
- FireMarshal 代码验证：
  - `software/firemarshal/wlutil/config.py`
  - `software/firemarshal/wlutil/build.py`
- 同目录现有 workload 验证：
  - `command` 已被用于需要 shell 片段或环境变量的 workload。

## 风险 / 后续
- 这次修改只修 workload 入口语义，不改变 runtime、AGFI、trigger 值或 guest env。
- 还需要重新跑 `image-closure` 验证构镜确实恢复正常。
- 构镜通过后才能继续新的 instruction-trigger FireSim round。
