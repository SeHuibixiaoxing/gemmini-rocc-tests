## Change

Updated the remote gdbserver SOP after checking current target ELF symbols.

## Files

- `pipeline-runtime/docs/testing/gdbserver_integration_sop.md`

## Rationale

The SOP previously included `break hw_dma_fence` in the first cfg32 NIC
breakpoint set. The current `rerocc_pipeline_runtime-linux` ELF does not expose
`hw_dma_fence` as a stable symbol because it is a `static inline` helper in
`prt_dma.c`. Using that breakpoint during the first `gdbserver --once` attach
would be a needless source of confusion.

## Validation

Ran `riscv64-unknown-linux-gnu-nm` on
`generators/gemmini/software/gemmini-rocc-tests/build/rerocc-linux-tests/rerocc_pipeline_runtime-linux`
and confirmed the remaining first-breakpoint symbols exist:
`prt_runtime_run`, `prt_action_bind_topology`, `stage_prepare_exec_views`,
`prt_dma_submit`, `prt_dma_wait`, `dma_blocking_wait`,
`prt_gemmini_spm_xlate_program`, `prt_gemmini_spm_xlate_flush`,
`prt_rr_release_scope`, `prt_gemm_conv_run`, and `prt_gemm_fence`.
