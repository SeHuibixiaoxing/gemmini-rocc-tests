## 修改内容

本轮没有直接改功能语义，而是在 target TX 出口链路上加入可综合 snapshot：

- `hPort.nicOut` 最近 8 个 payload flit：
  - `data`
  - `keep`
  - `last`
  - packet 内 flit index
- `NICTokenToBigTokenAdapter` 最近一次 `pcie_out.fire` 的完整 512-bit bigtoken：
  - word0 为 LRV/header
  - word1..word7 为 7 个 data flit
- host `simplenic` 在 `target_to_switch_pull` token debug 时同步打印：
  - `SIMPLENIC TX SNAPSHOT ... last_bigtoken=...`
  - `SIMPLENIC TX SNAPSHOT ... hist[i] flit_idx=... keep=... last=... data=...`

## 调试目的

当前 pcap 和 token debug 已经证明：

```text
target Linux checksum 之后
  -> IceNet TX / SimpleNIC / CPU-managed stream / F2 PCIS read
  -> target_to_switch_pull
```

这段链路中存在确定性 bit-clear。新 snapshot 用来区分：

- 如果 `hPort.nicOut` history 已经坏：继续查 IceNet `StreamReader` / `Aligner` / send path。
- 如果 `hPort.nicOut` 好、`NICTokenToBigTokenAdapter.pcie_out` 坏：查 bigtoken pack / flush。
- 如果 `pcie_out` 好、host `target_to_switch_pull` 坏：查 CPUManagedStreamEngine to-host unpack 或 F2 PCIS 512-to-64 read bridge。
