## 修改内容

- 在 `testchip_tsi_t` 中新增 plusarg-gated host 诊断开关：
  - 识别 `+tsi_bootdiag`
  - 识别 `+tsi_bootdiag=1`
- 在 `testchip_tsi_t::reset()` 中新增两条 host 侧诊断输出：
  - `[tsi-bootdiag] entering tsi_t::reset for hart0 msip`
  - `[tsi-bootdiag] returned from tsi_t::reset`
- 在 `testchip_tsi_t::write_chunk()` 中对非 loadmem 路径下的
  `addr=0x2000000, nbytes=4` 做特判输出：
  - `[tsi-bootdiag] write_chunk addr=0x2000000 nbytes=4 data=0x1`
- 新增 bootdiag runtime config 变体，并通过
  `metasimulation_only_plusargs` 注入：
  - `+tsi_bootdiag=1`
  - 保留原有 `+fesvr-step-size=128 +max-cycles=100000000`

## 修改原因

- 上一轮静态 + live 证据已经把问题缩到 boot ROM 唤醒最后一步：
  host 侧 loadmem/TSI 都排空，但 hart0 仍未被有效唤醒。
- 继续在 guest 侧或随机位置加 breadcrumb 只会移动卡点，
  无法回答“最后那笔 CLINT `MSIP` 写到底有没有发出”。
- 这轮修改的目标是把问题直接二分为：
  - host 是否进入 `tsi_t::reset()`
  - 若进入，`0x2000000 <- 1` 是否真的调用
