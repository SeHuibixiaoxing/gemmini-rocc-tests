- 但 guest 只跑最简单 baremetal smoke

## 修改动机

之前 `cfg32 + NIC + gdbserver` FPGA run 的失败点已经被静态收敛到
`SimpleNIC` host bridge 极早阶段。

这时继续直接上 FPGA / Linux / gdbserver 会把问题空间混在一起：

- guest Linux
- workload
- gdbserver
- NIC
- FPGA host path

因此需要一条更小的控制路径，只验证：

- `networked topology`
- `switch`
- `SimpleNIC`
- 最基础 guest bring-up

## 语义影响

这两个新配置文件不改变现有主线 workflow 语义，只新增一条调试用控制路径。

这条路径的语义是：

- “在 FireSim manager 正规流下，用最小单核 Rocket + NIC +
  baremetal hello 复现/排除 `SimpleNIC` 级别问题”

它的价值在于：

- 把 NIC 基础桥接正确性与
  `pipeline-runtime / Gemmini / ReRoCC / Linux`
  主线问题解耦

## 风险 / 后续

- 这轮验证的是“当前源码 + local metasim”，不是旧 FPGA AGFI。
- 因此它证明：
  - 当前 `SimpleNICBridge` 修复通过了最小 NIC smoke
  - 但还不能直接替代 FPGA NIC 路径验证
- 下一步应优先在包含最新源码的 NIC bitstream 上，
  先做一轮尽量接近这条 smoke 的 FPGA NIC 最小验证；
  若通过，再恢复 Linux/gdbserver/pipeline-runtime 主线。
