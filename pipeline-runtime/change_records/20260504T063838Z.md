# Change Record 2026-05-04 06:38 UTC

Category: gdbserver

## Goal

Add a deeper synthesizable SimpleNIC observation surface before any further
hardware rebuild is needed. The purpose is to reduce future bitstream iterations:
if the current or next NIC/gdbserver run fails, a single host-side
`dump_host_debug()` should identify the deepest reached point in the
host-switch-stream-adapter-target chain.

## Change

`SimpleNICBridge.scala` now exposes additional read-only CSR/MCR state:

- `progress_seen_mask`, `last_progress_event_mask`, and `last_progress_cycle`
  to show the deepest chain milestone reached.
- Current and maximum continuous blocked streak counters.
- Sticky ever-valid/ready/fire/blocked masks for target-to-host and
  host-to-target channel surfaces.
- Last blocked ready/valid/fire/block masks plus queue and adapter snapshots.
- First/last from-host and to-host blocked edge snapshots.
- Payload/empty counters for host-to-NIC enqueue, target NIC input fire, and
  NIC-to-host enqueue/dequeue.
- Last event cycle/data/meta snapshots for:
  - `htnt_queue` enqueue/dequeue;
  - target `nicIn` fire;
  - target `nicOut` fire;
  - `ntht_queue` enqueue/dequeue.
- First payload milestone cycles for host-to-NIC payload enqueue, target input
  payload fire, target output payload fire, NIC-to-host payload enqueue, and
  PCIE-to-host fire.

`simplenic.h` appends the corresponding MMIO fields after the existing debug
registers, preserving all old offsets.

`simplenic.cc` extends `dump_host_debug()` so every mismatch/blocking dump
prints the new progress masks, sticky masks, blocked edge snapshots, chain
counts, first milestone cycles, and last event data/meta.
