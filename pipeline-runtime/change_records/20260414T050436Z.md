## 修改原因

- 当前 authoritative blocker 已经不是 late pointwise；
  新 capture 把前沿收敛到
  `stage_prepare_exec_views() -> fixed-load tensor=1000001`
  内部。
- 旧代码在这个窗口里只有
  `stage-fixed-load-sparse begin/end`
  和 page breadcrumb；
  一旦挂在第一个 breadcrumb 之前，现有日志无法区分：
  - page setup
  - bounce buffer 选择
  - `prt_host_virt_to_phys()`
  - 还是真正的 DMA submit
- 固定 profile 之前把
  `PIPELINE_RUNTIME_DMA_FIXED_LOAD_PROBE_ENABLE`
  关掉了，导致已有 fixed-load probe 根本不会生效。

## 代码修改

- `src/prt_dma.c`
  在 `dma_copy_host_to_spm_pages_linux()` 的 fixed-load probe 条件下新增：
  - `phase=page-setup`
  - `phase=bounce-begin`
  - `phase=bounce-end`
  - `phase=v2p-begin`
  - `phase=v2p-end`
- 这些日志只在现有 fixed-load probe 命中的页上触发，
  保持低扰动，不扩散到普通 export / pointwise 热路径。
- 同时给 `prt_host_virt_to_phys()` 包了一层
  `prt_host_virt_to_phys_debug_scope_push/pop`，
  为后续必要时开启更深 v2p 观测预留 narrow scope。

- `scripts/pairdummy_sbus128_fixed_env.sh`
  将
  `PIPELINE_RUNTIME_DMA_FIXED_LOAD_PROBE_ENABLE`
  从 `0` 改为 `1`，
  让下一轮 fixed profile 直接带上 fixed-load probe。
