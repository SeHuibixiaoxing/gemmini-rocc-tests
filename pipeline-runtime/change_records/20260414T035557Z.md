## 修改原因

- 当前卡点排查仍有大量手工 `grep + tail + decode` 往返，速度慢，也容易在没有先读代码的情况下过早解释日志。
- 原来的 artifact audit 还没把 `vAccIdxList / pAccIdxList / splitKind / model layer / RR cfg stage budget`
  这些静态约束全部机器化。
- 当前 runtime 的 `rr_cfg_id_for_stage()` 仍有一个 latent risk：
  `cfg15` 保留给 `spm_xlate`，因此 `8+` local stages 会产生新的配置冲突；
  这类问题应在 live run 前就挡住。

## 语义影响

- `audit_pipeline_runtime_artifact.py` 现在除了原有 transport / ring 语义检查外，还会检查：
  - `vAccIdxList` permutation
  - `pAccIdxList` 长度、唯一性、范围
  - stage 本地 SPM 元数据长度与 page span
  - stage `splitKind`
  - model layer 类型与 stage 的兼容性
  - segment 总 `accUtil`
  - segment local stage 数是否越过当前 RR cfg 预算
- 新增 `scripts/triage_prt_capture.py`：
  - 输入 capture 目录或单个 breadcrumb / sparse log
  - 自动汇总最新 sparse frontier
  - 结合 breadcrumb 给出当前 frontier 所在边界和下一步建议
- 主文档现在明确要求：
  先静态审计和代码阅读，再做 capture 分诊，最后才加新日志。
