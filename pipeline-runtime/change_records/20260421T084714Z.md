## 修改内容

### 1. 新增 pairdummy gdbserver 网络前置审计脚本

新增：

- `audit_pairdummy_networked_gdbserver_target.sh`

职责：

- 在本地静态检查当前 `sims/firesim-staging/generated-src` 下，
  与 `pairdummy 4c12p12 sbus128` 对应的生成目标目录
- 抽取其中 DTS
- 判断是否存在 guest NIC 的设备树证据：
  - `ice-nic`
  - `nic@10016000`
  - `ethernet`

同时也输出：

- 是否存在 `blkdev-controller@10015000`

这样能快速区分：

- “target 至少有 block device、DTS 是正常的”
  与
- “target 完全没有 NIC 设备节点”

### 2. workflow 改为在 networked gdbserver 场景下 fail-fast

在 `pairdummy_sbus128_workflow.sh` 中新增：

- `network_audit_script`
- `network-audit` 子命令
- `verify_networked_gdbserver_target_prereqs`

并把该前置校验接到：

- `launch`
- `infrasetup`
- `network-prepare`
- `run`

触发条件：

- `PIPELINE_RUNTIME_GDBSERVER_ENABLE != 0`
- 且 `runtime_topology == example_1config`
- 且没有显式设置 `PAIRDUMMY_SKIP_NETWORK_GDBSERVER_TARGET_AUDIT=1`

效果：

- 如果当前生成目标没有 NIC，workflow 会在本地直接报错退出
- 不再继续拉起 F2 run farm 浪费机时

### 3. SOP 更新

`gdbserver_integration_sop.md` 现在明确加入：

- `example_1config` 只定义 manager/runtime 的网络拓扑，不会替 target 自动补 NIC
- 当前 12-pair `sbus128` 生成物已经静态证实不含 IceNIC
- 在新的 `WithNIC` bitstream 出来之前，不应继续对当前 AGFI 做 guest TCP `gdbserver`
- 运行前可直接执行：
  `pairdummy_sbus128_gdbserver_workflow.sh network-audit`

## 这次改动解决的问题

之前 workflow 的问题是：

- host 侧 `tap0` 已经准备好了
- guest 侧 `gdbserver` 也已经能 listen
- 但因为根因是 bitstream 无 NIC，
  所以后续每一轮 run 都注定不会出现可 attach 的 guest IPv4

这种情况下继续起机，只会重复得到：

- `guest_ipv4=unknown`
- `No route to host`
- `ip neigh FAILED`

现在 workflow 会在更早的位置把这件事说清楚并拦下。
