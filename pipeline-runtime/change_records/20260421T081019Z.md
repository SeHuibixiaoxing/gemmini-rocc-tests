## 修改内容

### 1. gdbserver runtime 改为 networked topology

在 gdbserver 专用 runtime YAML 中：

- 将 `target_config.topology` 从 `no_net_config` 改为 `example_1config`
- 保留 `no_net_num_nodes: 1`

原因：

- topology 需要切到 FireSim 的 1-node networked cluster
- 但 manager parser 当前仍会无条件读取 `no_net_num_nodes`
  所以该字段必须保留作为兼容项

### 2. workflow 自动执行 network prepare

在通用 `pairdummy_sbus128_workflow.sh` 中新增：

- `runtime_topology` 解析
- `network-prepare` 子命令
- `run` 前的自动 `maybe_prepare_networked_gdbserver`

并新增 helper：

- `prepare_firesim_networked_gdbserver.sh`

该 helper 会：

- 找到最新的 `switch0-*-build`
- 提取 shmem link id
- 将 `switchconfig.h` 改写为 `SSHPort(1)` 版本
- 重新 `make` 并下发 `switch0`
- 在 run host 上建立 `tap0=172.16.0.1/16`

helper 后续又补了两轮修正：

- 让它对已 patch 的 `switchconfig.h` 幂等
- 修正 `sed/awk` 解析问题，避免因为缩进与 regex 误写导致误报

### 3. guest 侧网络与 gdbserver netdev 探测修正

新增 workload-local：

- `overlay/etc/init.d/S40network`

第一轮修正：

- 若没有 `eth0`，退化为选择第一个非 `lo` 接口

第二轮修正：

- 该策略会误选虚拟接口，所以进一步收窄为：
  - `/sys/class/net/<if>/device` 存在
  - `type=1`
  - MAC 非全零

同样两轮修正也同步到了 runner：

- `run_rerocc_pipeline_runtime_bertmini.sh`
- workload overlay 副本

使 `gdbserver.info` 中的 `net_dev` 与 `guest_ipv4` 探测逻辑和 guest bring-up 保持一致。

### 4. 更新 SOP

`gdbserver_integration_sop.md` 现在已同步为：

- runtime topology 已是 `example_1config`
- workflow 会自动执行 network prepare
- host 侧 topology blocker 已移除
- 当前剩余 blocker 已转成 guest netdev/IPv4

## 动态验证结论

本轮实际跑了多轮 FPGA：

- 第一轮证明：
  - `tap0` 可 `LOWER_UP`

所以当前剩余 blocker 已经不是 FireSim 无网络，而是 guest 中没有出现可用 netdev。
