## Summary

Added a runtime DMA manager ownership guard. Before acquiring a DMA ReRoCC
scope, directly submitting a DMA token, or taking the host `spm_va` path, the
runtime now checks that the requested manager belongs to the current action's
stage assignment.

The guard accepts:

- the stage's assigned DMA manager;
- in pair-manager mode, any paired manager in the stage's Gemmini manager set.

It rejects out-of-range stages and unassigned managers with a clear diagnostic.

## Limitations

This checkpoint is not an FPGA or gdbserver validation. It is intended to catch
software manager misuse before a hardware run reaches DMA wait/fence ambiguity.
