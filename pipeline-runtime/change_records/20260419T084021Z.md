## 修改内容

### 1. 新增记录分类索引脚本

新增：

- `scripts/generate_record_category_index.py`

作用：

- 扫描 `debug_records/*.md`
  与 `change_records/*.md`
- 用稳定规则把记录归到：
  - `main`
  - `tracev`
- 生成两个索引文件：
  - `debug_records/CATEGORY_INDEX.md`
  - `change_records/CATEGORY_INDEX.md`

并同步在两个 README 中声明：

- 原始记录仍保持扁平 UTC 时间戳命名
- 按类别阅读时使用 `CATEGORY_INDEX.md`

### 2. 新增更细的 DMA breadcrumb phase

在 `include/prt_breadcrumb.h` 中新增：

- `PRT_BREADCRUMB_PHASE_DMA_PAGE_AFTER_SUBMITWAIT_RETURN = 118`
- `PRT_BREADCRUMB_PHASE_DMA_PAGE_AFTER_PAGE_END = 119`
- `PRT_BREADCRUMB_PHASE_DMA_PAGE_AFTER_ACCOUNTING = 120`

并在 `scripts/decode_prt_breadcrumb.py` 中同步 phase 名字。

### 3. 在 `dma-export` 热路径补 phase

在 `src/prt_dma.c` 的
`dma_copy_spm_pages_to_host_linux()`
中，为当前最关注的
`stage=0 / tensor=2`
export 路线新增 3 个 breadcrumb 点：

1. `dma_page_after_submitwait_return`
   - `dma_submit_wait_annotated_scoped()` 返回后
   - `dma_breadcrumb_page_end()` 之前
2. `dma_page_after_page_end`
   - `dma_breadcrumb_page_end()` 与 `sw-e` 之后
3. `dma_page_after_accounting`
   - `copied += chunk`
   - `remaining -= chunk`
   之后

这些点只走 binary breadcrumb，
不新增新的热路径字符串日志。

## 修改原因

- 现有记录表明：
  - 主线低扰动 frontier 一度收敛到 `spm-xlate restore-begin`
  - 后续 `TraceV/workerpc` 分支又证明 freeze 会在
    `stage=0 / subbatch=1 / tensor=2 export DMA`
    热路径上再次暴露
- 静态读代码后确认，
  当前最值得切细的 caller-side 小窗口就是：
  `dma_submitwait_after_cleanup -> dma_page_end -> page accounting`
- 与其继续加文本日志或 shell probe，
  更符合约束的做法是补更细的 breadcrumb phase。

## 语义影响

- 不改变 runtime 计算语义、DMA 语义、RR 语义或硬件行为。
- 只增强两件事：
  1. 记录组织方式
  2. `dma-export` 热路径的二进制观测粒度
