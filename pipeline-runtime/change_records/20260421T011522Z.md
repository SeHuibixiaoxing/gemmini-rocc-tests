# Change Record 20260421T011522Z

调试类别：main

本轮为 `pipeline-runtime` 主线调试补了一条新的低扰动 breadcrumb 观测链路，用来绕开当前 `page29/token0 -> slot14` 的 torn/collision 歧义。

## 目标

- 不再把下一轮 rerun 的关键判别点压在 `slot14`
- 在不引入高扰动日志的前提下，判断程序是否已经进入 `page29` 的 direct path
- 让新 breadcrumb 同时携带 alias target 身份，避免“到了 page29，但不知道是哪个 export target”的二次歧义

## 修改内容

- 新增 breadcrumb phase：
  - `PRT_BREADCRUMB_PHASE_DMA_PAGE_DIRECT_PATH_DECIDED`
- 在 breadcrumb 模块中增加一组 thread-local export target token API：
  - `prt_breadcrumb_set_export_target_token()`
  - `prt_breadcrumb_clear_export_target_token()`
  - `prt_breadcrumb_get_export_target_token()`
- 在 `copy_tensor_pages_to_model_alias_target()` 中：
  - 把去重后的 `target_seq` 编码成 `token_id = target_seq + 1`
  - 仅在这次 DMA 导出调用期间生效
- 在 `dma_copy_spm_pages_to_host_linux()` 中：
  - direct path 上新增一条 breadcrumb
  - 位置位于 `dma_chunk_needs_bounce(...) == false` 之后、`before_v2p` 之前
  - 新 probe 使用 scoped alias target token，而不是固定 `token_id=0`
- 在 `decode_prt_breadcrumb.py` 中补充新 phase 名称，保证解码输出可读

## 原因

- 当前 `page29/token0` 的 page-level notes 会命中 `slot14`
- `slot14` 先前已被两份 live capture 证明存在 odd torn state，不能继续作为单一判别依据
- `tensor_id=2` 在当前 `bertmini` 主线里只有两个 unique alias target，因此 `target_seq + 1` 足够把这两条 direct-path probe 和 `token0` 路径分开

## 验证

- `python3 -m py_compile pipeline-runtime/scripts/decode_prt_breadcrumb.py pipeline-runtime/scripts/generate_record_category_index.py`
- 静态核对 `model.layers.yaml`：
  - `tensor_id=2` 的 unique alias target 为 `0x20400` 与 `0x842400`
  - 对应 `target_seq=0/1`

## 影响范围

- 本轮不改变现有 page-level breadcrumb 的 `token_id=0` 语义
- 本轮新增 probe 只影响：
  - `segment0/stage0/tensor2` 这一条当前主线关注的 export direct path
- 本轮尚未触发新的 FireSim rerun；实际效果要以下一轮 `runworkload` 结果为准
