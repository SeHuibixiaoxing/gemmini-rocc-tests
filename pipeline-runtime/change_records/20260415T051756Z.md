# 2026-04-15 05:17:56 UTC Change Record

## Scope
- File changed:
  - `/home/ubuntu/chipyard/scripts/firesim-tmux-run.sh`

## Motivation
- During the fresh rerun on instance `i-026f018c64c851dd7` / `192.168.1.154`:
  - `guest_sparse` advanced past the earlier trigger window,
  - but `guest_trigger` remained `0`.
- Static review showed the cause:
  - `firesim-tmux-run.sh` explicitly propagated `FIRESIM_*` and a few tool env vars into the generated tmux `command.sh`,
  - but it did **not** propagate `PIPELINE_RUNTIME_DEBUG_TRIGGER_*`.
- Therefore a shell-side trigger overlay could silently disappear when the actual FireSim manager command was run in tmux.

## Change
- Extended the tmux wrapper's environment propagation rule to also include:
  - `PIPELINE_RUNTIME_DEBUG_TRIGGER_*`

## Intended Effect
- Future trigger-gated reruns launched through:
  - `/home/ubuntu/chipyard/scripts/firesim-tmux-run.sh`
  - and the pairdummy workflow layered on top of it
- will reliably preserve the intended trigger overlay inside the detached tmux command environment.

## Risk
- Low.
- The propagation scope is intentionally narrow:
  - only the existing trigger overlay family is added,
  - not arbitrary `PIPELINE_RUNTIME_*` variables.
