## 目标

- 在不改 guest/runtime 业务语义的前提下，
  补齐 `TracerV` round 的 host-side 取证能力。
- 解决当前问题：
  host watchdog 超时后会自动回收实例，
  但之前不会抓回 `TRACEFILE-C*`，
  导致每轮都只能看到 guest 文件前沿，拿不到最后的退休指令证据。

## 修改内容

- 新增 trace capture 相关环境参数：
  - `FIRESIM_MONITOR_TRACE_GLOB`
  - `FIRESIM_MONITOR_TRACE_TAIL_LINES`
- 在 `capture_remote_state()` 里新增：
  - 读取运行中的 `FireSim-f2` pid
  - 抓取 `/proc/<pid>/cmdline`
  - 抓取 `/proc/<pid>/fd` 中指向 `TRACEFILE-C*` 的 fd 映射
  - 抓取 `TRACEFILE-C*` 的 `ls -l` 和 `wc -c` 元数据
  - 对每个 trace 文件抓取尾部文本到单独的 `*.tail.txt`
- trace 相关远端读取统一改为 `sudo`，
  避免 `sudo ./FireSim-f2` 生成的文件因权限导致 capture 为空。

## 原因

- 本轮 live run 的实例
  `i-08d0bc88c0f18cc9d`
  不是先被 manager 弄丢，
  而是被 host watchdog 在
  `2026-04-17 12:14:22 UTC`
  idle timeout 后主动 terminate。
- watchdog 的 guest capture 已经足够证明：
  runtime 进入了
  `stage-fixed-load-sparse slot=1 tensor=1000001`
  窗口，
  但由于没有把 `TRACEFILE-C*` 一起抓回，
  仍然无法回答“卡在哪条指令”。
- 下一轮如果继续只依赖 guest 文件，
  仍会重复同样的信息缺口。

## 风险 / 后续

- `TRACEFILE-C*` 若非常大，
  当前只抓尾部 `4000` 行；
  若后续发现不足，可再调 `FIRESIM_MONITOR_TRACE_TAIL_LINES`。
- 当前抓取策略假定 `trace-output-format=0` 为文本；
  若后续改成二进制格式，需要把 tail 抓取改成按字节。
- 这轮改动是纯 observability 增强；
  下一轮应先复跑同一 `tracerv-inst` 路径验证证据回收，
  再决定是否继续改 TracerV/trigger 逻辑。
