# 2026-05-03T23:27:10Z - gdbserver / NIC target->host stream latch fix

类别：`gdbserver` / NIC / FireSim CPU-managed stream

## 改动内容

### `sims/firesim/sim/midas/src/main/scala/midas/core/CPUManagedStreamEngine.scala`

- 修改 `StreamWidthAdapter` 的 wide-to-narrow 路径。
- 新增：
  - `wide_data: Reg(Vec(beats, UInt(narrowW.W)))`
  - `wide_valid: RegInit(false.B)`
- `io.wide.in.fire()` 时一次性锁存完整 wide beat。
- 后续 `io.narrow.out.bits` 只从 `wide_data(wide_beats)` 输出。
- `io.wide.in.ready := !wide_valid`，避免一个 512-bit beat 在 8 次 64-bit CPU/PCIS drain 期间继续组合依赖上游。
- 最后一个 narrow beat fire 后清空 `wide_valid`。
- 顺带把 CPU-managed AXI 单次最大 transfer 收紧到 `math.min(4096, axiBeatBytes * 256)`，在 F2 上等价于 2048B，避免过长的 destructive read/write 事务。

### `generators/firechip/goldengateimplementations/src/main/scala/SimpleNICBridge.scala`

- 保留 `pcieOutQ = Queue(UInt(512.W), 2)`，继续隔离 `NICTokenToBigTokenAdapter` 和 `streamEnq`。
- 增加 `pcie_out` 阶段 8 个 64-bit word 的 enq/deq snapshot：
  - `debug_last_pcie_out_enq_words`
  - `debug_last_pcie_out_deq_words`
- 暴露为 CR：
  - `nicbig_last_pcie_out_enq_word0..7_{0,1}`
  - `nicbig_last_pcie_out_deq_word0..7_{0,1}`
- `minObsBuildMarker` 设为 `0x05030003`。
- 对 `minObsBuildMarker` 加 `dontTouch`，修复之前只读 marker 被优化掉、生成 SV 中 CR read port 没有真实连接的问题。

### `generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.h`

- 在 `SIMPLENICBRIDGEMODULE_struct` 中加入新的 `pcie_out_enq/deq` snapshot CR 字段。

### `generators/firechip/bridgestubs/src/main/cc/bridges/simplenic.cc`

  - `pcie_out_enq w0..w7`
