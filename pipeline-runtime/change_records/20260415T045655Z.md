# 2026-04-15 04:56:55 UTC Change Record

## Scope
- File changed:
  - `src/prt_page_table.c`

## Motivation
- Latest authoritative capture stalled after:
  - `dfix ph=v2p-b seg=0 gs=0 ls=0 sb=4 mgr=0 tn=0 pg=1`
- Static analysis showed:
  - the synthetic model blob is `mmap + prefault + mlock`;
  - its base is `0x3fb3c7a000`, 4 KiB aligned;
  - logical page `0` and logical page `1` for `tensor=0` still fall within the same host 4 KiB page.
- Therefore the next question is not “which logical page”, but “which internal sub-step of `prt_host_virt_to_phys()`”.

## Change
- Added narrow trigger-log sub-events inside `prt_host_virt_to_phys()`:
  - `iv2p-b`
  - `iv2p-fd`
  - `iv2p-pb`
  - `iv2p-pe`
  - `iv2p-rf`
  - `iv2p-np`
  - `iv2p-p0`
  - `iv2p-ok`
- These events only fire when `t_prt_host_v2p_debug_scope` is non-null.
- The fixed-load direct/bounce path already sets that scope around the `prt_host_virt_to_phys()` call, so no new environment variable was introduced.
- The events reuse the existing trigger-log infrastructure and remain compatible with the current trigger-gated workflow.

## Intended Effect
- On the next trigger-gated rerun, we can distinguish:
  - blocked before `pread`
  - blocked in `pread`
  - `pread` returned but entry invalid / not present
  - translation fully completed and the stall is actually after `v2p`

## Risk
- Low to moderate observability risk:
  - this adds a handful of extra trigger lines in a path already under trigger capture;
  - it does not enable deep logs globally;
  - it does not add foreground `sync`;
  - it does not change runtime semantics.
