# 补充 F2 runfarm 及时回收约束

日期：2026-05-03T08:52:03Z

## 背景

发现一台旧 FireSim F2 runfarm 实例仍处于 `running`：

```text
instance: i-0f0c965a715efb669
type:     f2.6xlarge
cluster:  f2rocketsinglecorenictcdebug
private:  192.168.2.164
launch:   2026-05-03T03:09:54Z
```

该实例来自 `config_runtime_f2_rocket_singlecore_nic_gdbserver_smoke_notrace_relaxed_targetcycle_preserve_30mhz.yaml`
对应的 runfarm。后续没有有效 live 调试会话继续使用它，应及时回收。

## 修改文件

```text
AGENTS.md
generators/gemmini/software/gemmini-rocc-tests/pipeline-runtime/docs/constraints/hard_constraints.md
generators/gemmini/software/gemmini-rocc-tests/pipeline-runtime/docs/testing/gdbserver_integration_sop.md
```

## 修改内容

- 在仓库通用 FireSim workflow 约束中补充：每次 F2 live inspection 和现场
  copy-back 完成后必须及时关闭 runfarm；
- 在 pipeline-runtime hard constraints 中补充：切换任务、结束一轮调试、
  启动下一轮 runfarm 前必须检查 stale `f2.*` 实例；
- 明确如果 `terminaterunfarm` 后 EC2 仍是 `running`，必须用
  `aws ec2 terminate-instances` 手动回收并复查。
- 在 gdbserver SOP 的失败现场处理处补充同样的 `f2.*` EC2 复查和手工回收要求。

## 现场处理

- 已执行对应 runtime/hwdb/recipe 的：

```text
firesim terminaterunfarm --forceterminate
```

- FireSim manager 明确列出并终止：

```text
i-0f0c965a715efb669
```

- 同时关闭旧的 `rocket-singlecore-nic-oldshape-gdb-regress-launch-20260503-0830`
  tmux launch 会话，避免它在容量恢复后重新申请 F2。

## 后续约束

任何 FPGA run 调试结束前，必须把 F2 EC2 状态检查作为固定收尾项：

```text
aws ec2 describe-instances --filters \
  Name=instance-state-name,Values=pending,running,stopping,stopped,shutting-down \
  Name=instance-type,Values=f2.*
```

如果仍有相关 `f2.*` 实例处于 `running`，不得结束该轮调试。
