## 修改内容

在 `firesim_pcis_width_bridge_512_to_64` 中修改 `read_lane_mask()`：

- 旧行为：按 shell 侧 `ARSIZE` 决定读多少个 64-bit lane；`ARSIZE=6` 时选择 `8'hff`，一次 wide read 消费 8 个 downstream beat。
- 新行为：始终只选择 `addr[5:3]` 对应的一个 64-bit lane，一次 host read 只消费一个 downstream beat。

## 修复目的

F2 shell PCIS 总线是 512-bit，并且 shell 侧会以 `ARSIZE=6` 表达 BAR4 read；但 FireSim F2 host 侧 CPU-managed stream read 使用的是 `fpga_pci_peek64()`。CPUManagedStreamEngine 的 read 会从 FIFO 中 destructive dequeue。旧 bridge 把一个 host 64-bit read 放大成 8 个 FIFO dequeue，会丢弃 NIC to-host stream 中 7/8 的数据。

本轮修复让 F2 PCIS bridge 的 read 消费粒度与 `simif_f2.cc` 的 `peek64` 软件语义一致。
