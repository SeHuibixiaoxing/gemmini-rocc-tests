## 修改文件

- `rerocc-linux-tests-coupleddma/workload/host-init.sh`

## 修改原因

- 当前主线在 `image-closure` 阶段会触发本地 Linux workload 重编译。
- 该路径隐含依赖生成文件
  `software/gemmini-rocc-tests/include/gemmini_params.h`，
  但这个 header 在当前工作区缺失。
- 缺失后 make 暴露出来的是误导性的上层报错：
  `No rule to make target 'rerocc_gemmini_conv_matrix-linux'`，
  实际根因是头文件未恢复。
- 文档要求优先做最小、静态优先、guest-file-first 的修复，
  因此不适合改 Makefile 结构或引入新的构建分支。

## 修改内容

- 在 `host-init.sh` 中新增
  `ensure_generated_gemmini_params_header()`：
  - 目标路径：
    `software/gemmini-rocc-tests/include/gemmini_params.h`
  - 回退来源：
    `software/libgemmini/gemmini_params.h`
  - 仅当目标文件缺失时才执行恢复
- 在 `build_linux_binaries()` 进入实际编译前调用该函数，
  让固定 workflow 的本地 rebuild 能自动自愈这个缺失头文件

## 语义影响

- 不改变任何 pipeline runtime / DMA / trigger / workload 的执行语义。
- 不改变固定 profile 的环境变量约束。
- 不改变 `PIPELINE_RUNTIME_MLOCKALL_MODE=2`、
  不引入 doneflag polling、
  不改变 debug trigger overlay 族。
- 影响仅限于：
  当工作区缺少生成的 `gemmini_params.h` 时，
  在本地编译前从现有 canonical fallback 自动补回。
