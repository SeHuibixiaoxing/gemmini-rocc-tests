## 修改原因

- 旧 breadcrumb 只能稳定落到 `rr_acquire_after_call` 等外层边界，容易把更深层的 pointwise stall 误判成 RR acquire 卡住。
- 现有 sparse log 已证明真正前沿在 late pointwise / Gemmini 区间，需要更靠近 inner matmul 的低扰动边界。
- 这类能力如果不回写文档，下一轮接手仍然会沿用旧解释。

## 语义影响

- 新增 `gemmini` breadcrumb kind。
- 新增 4 个 pointwise phase：
  - `gemmini_pointwise_call_begin`
  - `gemmini_pointwise_call_return`
  - `gemmini_pointwise_matmul_begin`
  - `gemmini_pointwise_matmul_return`
- `decode_prt_breadcrumb.py` 现在会把这些 phase 解码成可读名称，并附带：
  - input / output / weights 指针
  - `dim_J`
  - `dim_K`
  - fallback type
