## 修改内容

### 1. 记录每个 TracerV bridge 的 host-side pull 统计

在 `tracerv_t` 中新增：

- `tracerno`
- `reported_first_nonzero_pull`
- `total_pulled_bytes`
- `total_nonzero_pulls`

用于记录：

- 是否出现过第一次非零 host pull
- 总共发生过多少次非零 pull
- host 累计拉到了多少 bytes

### 2. 第一次真正 pull 到数据时，立刻在 host stderr 打点

当 `process_tokens()` 第一次返回 `bytes_received > 0` 时，
现在会输出一条明确日志：

- `TracerV[<core>]: first nonzero host pull bytes=... selector=... min_batch_beats=... tracefile=...`

这条日志的意义是：

- 一旦出现，就能直接证明
  **host driver 已经真实从 FPGA stream 拉到了 trace token**
- 后续即使 `TRACEFILE-C*` 因 stdio 缓冲暂时还小于可见阈值，
  也不再会把它误判成 “compare 没命中”。

### 3. 在首次 nonzero pull 后立刻 flush 一次 trace file

首次 `bytes_received > 0` 后，
对 `tracefile` 增加一次 `fflush(tracefile)`。

目的：

- 让下一轮 live run 更容易在 run host 上直接看到
  `TRACEFILE-C*` 从 `0` 变成非零。

这不是每批次都 flush，
只在首次 nonzero pull 后做一次，
避免把 host-side I/O 扰动放大成持续性影响。

### 4. 在 `flush()` 结束时输出汇总

`flush()` 现在会额外打印：

- `TracerV[<core>]: flush summary nonzero_pulls=... total_bytes=...`

如果 workload 正常 finish 或 host driver 走到 `flush()`，
这条汇总可以补足：

- 到 run 结束为止到底有没有任何 host pull
- 如果有，一共拉了多少 trace bytes

## 目的与边界

- 只改 host-side TracerV driver。
- 不改 bitstream。
- 不改 target hardware / bridge RTL 语义。
- 不改 guest runtime 热路径。
- 这是一个纯观测增强补丁，
  用来把下一轮 `TracerV` 判断从
  “看 `TRACEFILE-C*` 猜”
  提升为
  “直接看 host 是否发生过 nonzero pull”。
