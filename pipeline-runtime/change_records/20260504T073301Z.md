# Change Record 2026-05-04 07:33 UTC

Category: gdbserver

## Goal

Add one more layer of synthesizable SimpleNIC observation before any next
hardware rebuild. The intent is to avoid a rebuild whose only purpose is "add
more debug": if the next NIC/gdbserver AGFI fails, the host-side debug dump
should identify the deepest ready/valid stage reached and the first/last
blocked snapshots.

## Change

This extends the previous `0x05040001` observation surface to
`minobs_build_marker = 0x05040002`.

New read-only CSR/MCR state:

- `BigTokenToNICTokenAdapter` now reports host-token valid/ready backpressure,
  latched valid/ready/last masks, current selected data, and the last emitted
  token data/meta.
- `NICTokenToBigTokenAdapter` now reports `ntht` fire/backpressure counters,
  PCIE-out ready/valid backpressure counters, and the last `ntht` token
  data/meta observed at the adapter input.
- Top-level SimpleNIC now reports the missing halves of queue handshakes:
  `htnt_queue_enq_valid`, `htnt_queue_deq_ready`,
  `ntht_queue_enq_valid`, and `ntht_queue_deq_ready`.
- Top-level SimpleNIC now records target-cycle ready/not-ready counts plus
  `to_host_ready_drive` and `from_host_ready` active counts.
- First blocked snapshots now include compact queue and adapter state, not just
  a blocked reason bitmask.
- First and last progress snapshots now include the progress event mask, cycle,
  compact queue snapshot, and compact adapter snapshot.

Host-side `dump_host_debug()` now decodes the compact queue/adapter snapshots,
prints the new adapter backpressure counters, and prints first/last progress
snapshots alongside the existing blocked/progress counters.
