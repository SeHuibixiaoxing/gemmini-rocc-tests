## 修改内容

### 1. SimpleNIC HostPort 方向解耦

把上一版仍偏 lockstep 的语义：

```scala
fromHostValidDrive = hPort.toHost.hValid && localQueuesReady
ntht_queue.io.enq.valid := tFire
htnt_queue.io.deq.ready := tFire
```

改为方向独立：

```scala
toHostReadyDrive = ntht_queue.io.enq.ready
fromHostValidDrive = htnt_queue.io.deq.valid
toHostFire = hPort.toHost.hValid && hPort.toHost.hReady
fromHostFire = hPort.fromHost.hValid && hPort.fromHost.hReady
ntht_queue.io.enq.valid := toHostFire
htnt_queue.io.deq.ready := fromHostFire
```

原因是 FAME 会用 per-channel fired state 允许一个 target cycle 的不同 channel 在不同 host cycle 完成；SimpleNIC 不能因为 output source 已经完成而撤掉 input sink valid。

### 2. 调试寄存器扩展

新增 SimpleNIC 可综合寄存器：

- `to_host_fire`
- `from_host_fire`
- `to_host_fire_count`
- `from_host_fire_count`
- `to_host_only_fire_count`
- `from_host_only_fire_count`
- `last_to_host_fire_cycle`
- `last_from_host_fire_cycle`

host dump 同步打印这些字段，用来区分：

- 两个方向都在推进；
- 只有 output source 推进；
- 只有 input sink 推进；
- 两个方向都被全局 target cycle 或本地队列挡住。

### 3. done 语义调整

`done` 从 `!tFire` 改为：

```scala
!(toHostFire || fromHostFire)
```

这样 host 侧轮询不会把“只有一个方向在本 host cycle 推进”的合法状态误判成完全空闲。
